# Кэширование и CDN — разборы

> 🌐 English version: [07-caching-cdn.answers.md](../en/07-caching-cdn.answers.md)

---

## Вопрос 1
Уровни: **браузер** → **CDN (edge)** → **reverse proxy/gateway** → **приложение
(Redis/in-memory)** → **буферный кэш БД**. Кэшировать ближе к пользователю выгодно,
потому что запрос **не идёт весь путь** до источника: короче задержка и меньше работы
на каждом нижележащем уровне (браузерный кэш вообще не выходит в сеть).

## Вопрос 2
**CDN** — сеть edge-серверов по всему миру, отдающих контент (обычно статику) с
ближайшего к пользователю узла. Выгоды: (1) **ниже задержка** — данные физически ближе;
(2) **разгрузка origin** — основной трафик оседает на edge, до твоего сервера доходит
малая часть (+ поглощение всплесков/части DDoS).

## Вопрос 3
- **Pull** — edge **сам подтягивает** контент с origin при первом промахе и кэширует;
  настраивается легко, кэш наполняется по спросу.
- **Push** — ты **заранее заливаешь** контент на edge-узлы; больше контроля, но больше
  работы.
**Pull** распространённее (проще).

## Вопрос 4
- **`Cache-Control: max-age=N`** — сколько секунд ответ считается **свежим**; пока свеж,
  берётся из кэша без запроса.
- **`ETag`** — «отпечаток» версии ресурса. При перепроверке браузер шлёт
  `If-None-Match: <etag>`; не изменилось → сервер отвечает **`304 Not Modified` без
  тела** (сэкономили трафик, кэш валиден дальше).

## Вопрос 5
1. **Версионирование имени файла** — `app.a1b2.js` (хеш контента в имени): поменялся
   контент → новое имя → браузер/CDN видят новый URL, старый кэш не мешает. Лучший приём
   для статики (можно ставить огромный max-age).
2. **Purge/invalidation** — явно сбросить объект в CDN через API, чтобы edge перетянул
   свежий с origin.

## Вопрос 6
- **Агрессивно кэшируемо:** статические ассеты (JS/CSS/картинки с версией в имени),
  редко меняющийся публичный контент (каталог, статьи).
- **Нельзя/осторожно:** персональные данные (баланс, личный кабинет), критично-свежее,
  ответы, зависящие от пользователя/авторизации → `no-store`/`private` или короткий TTL.

## Вопрос 7
Популярный объект с истёкшим TTL: множество запросов **одновременно промахиваются** на
edge и **разом бьют в origin** за свежей версией, создавая пик нагрузки, который может
уронить origin (см. cache stampede/thundering herd). Лечат: single-flight на edge,
stale-while-revalidate, джиттер TTL.
