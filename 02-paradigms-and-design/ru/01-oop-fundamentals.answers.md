## Вопрос 1
- **Инкапсуляция** — спрятать состояние за методами, чтобы объект сам берёг
  инварианты.
- **Абстракция** — показать «что», спрятать «как».
- **Наследование** — переиспользование по is-a.
- **Полиморфизм** — один интерфейс, разные реализации.

Главный — **инкапсуляция**: именно сокрытие состояния даёт модульность (можно менять
внутренности, не задевая клиентов). Остальные три обслуживают ту же цель.

## Вопрос 2
- **Абстракция** — про **дизайн интерфейса**: что показать наружу как существенное
  (`repo.save(user)`).
- **Инкапсуляция** — про **механизм сокрытия**: как спрятать и защитить остальное
  (приватные поля, инварианты в методах).
Абстракция решает *что показать*, инкапсуляция — *как спрятать и уберечь*.

## Вопрос 3
Проблемы наследования: (1) **жёсткая связь** — наследник знает внутренности предка,
меняешь базовый класс → ломаются наследники («хрупкий базовый класс»); (2)
**нарушение LSP** — наследуют по «звучит похоже», подтип не подставляется; (3) один
предок — **негибко** (нельзя комбинировать несколько поведений).

Композиция: вместо `class Car extends Engine` — `class Car { constructor(private
engine: Engine) }`. Машина *содержит* мотор и делегирует; мотор можно подменить,
скомбинировать несколько частей, связь слабее.

## Вопрос 4
`Stack extends Array` наследует **весь** интерфейс массива: `push`, но и `splice`,
`[i]=`, `length=0` — любой может обойти правила стека (LIFO) и залезть в середину.
Инкапсуляция нарушена (внутреннее хранилище торчит наружу), LSP тоже (Stack не
ведёт себя как полноценный Array и наоборот). Правильно — **композиция**:
```ts
class Stack<T> {
  #items: T[] = [];
  push(x: T) { this.#items.push(x) }
  pop() { return this.#items.pop() }
  get size() { return this.#items.length }
}
```
Массив спрятан внутри, наружу торчит только контракт стека.

## Вопрос 5
Полиморфизм — разные типы отвечают на один вызов по-своему, вызывающий код не
знает конкретный тип. Связь с OCP: добавить новый тип = новая реализация интерфейса,
**существующий код не меняется**.
```ts
// вместо switch(shape.type) — метод:
interface Shape { area(): number }
function total(shapes: Shape[]) { return shapes.reduce((s, x) => s + x.area(), 0) }
// новая фигура → новый класс implements Shape; total() не трогаем
```

## Вопрос 6
`class` — **синтаксический сахар над прототипным наследованием**. Под капотом методы
кладутся в объект-прототип (`Stack.prototype`), а экземпляр лишь **ссылается** на
него. При обращении `obj.method()` движок ищет `method` на самом объекте, не нашёл —
идёт по **цепочке прототипов** вверх. `extends` связывает прототипы child →
parent. Поэтому метод хранится **в одном месте** (прототипе), а не копируется в
каждый экземпляр — экономия памяти и общий источник.

## Вопрос 7
- **`#field`** — настоящий приватный слот на уровне языка: снаружи недоступен
  **в рантайме**, обращение — синтаксическая ошибка. Реально скрывает.
- **`_field`** — просто **соглашение** («не трогай»), поле полностью доступно;
  ничего не скрывает технически.
- **`private` в TS** — проверка только **на этапе компиляции**; в собранном JS поле
  обычное и доступно в рантайме.
Реально скрывает данные в рантайме только **`#field`**.
