# Паттерны GoF — разборы

## Вопрос 1
- **Порождающие** — как создавать объекты, пряча `new` за абстракцией (Factory
  Method, Abstract Factory, Singleton, Builder, Prototype).
- **Структурные** — как собирать объекты в большие структуры (Adapter, Decorator,
  Facade, Proxy, Composite, Bridge, Flyweight).
- **Поведенческие** — как объекты взаимодействуют и распределяют обязанности
  (Strategy, Observer, Command, State, Iterator, Template Method, Chain of
  Responsibility и др.).

## Вопрос 2
**Decorator.** Оборачиваем объект в другой с тем же интерфейсом, добавляя поведение:
```ts
interface Notifier { send(msg: string): void }
class BaseNotifier implements Notifier { send(m: string) {} }
class Slack implements Notifier {
  constructor(private n: Notifier) {}
  send(m: string) { this.n.send(m); /* + отправка в Slack */ }
}
new Slack(new BaseNotifier());   // комбинируется как угодно, без класса на комбинацию
```

## Вопрос 3
Все три оборачивают, но с разной **целью относительно интерфейса**:
- **Adapter** — *меняет* интерфейс: несовместимый приводит к тому, что ждёт клиент.
- **Facade** — *упрощает*: прячет много объектов/шагов за одним простым интерфейсом.
- **Decorator** — *сохраняет* интерфейс и *добавляет* поведение: на входе и выходе
  один и тот же контракт, но с довеском.

Мнемоника: адаптер — «переходник», фасад — «единая кнопка», декоратор — «обёртка с
начинкой».

## Вопрос 4
**Adapter.** Оборачиваем чужой логгер в свой интерфейс:
```ts
interface Logger { log(msg: string): void }
class LibLoggerAdapter implements Logger {
  constructor(private lib: LibLogger) {}
  log(msg: string) { this.lib.write('info', msg); }
}
```
Клиент продолжает звать `logger.log()`, ничего не зная про `write(level, msg)`.

## Вопрос 5
**Observer:** объект-субъект хранит список подписчиков и при изменении уведомляет
их всех, не зная, кто они и что делают. Расцепляет источник события и реакции.

Из коробки в JS:
- **`EventEmitter`** в Node (`emitter.on/emit`);
- **DOM-события** (`addEventListener`);
- **RxJS `Observable`**, реактивность **Vue**, подписки на стор (Redux `subscribe`,
  Pinia). Любой «подпишись — тебя позовут при изменении» — это Observer.

## Вопрос 6
- **Strategy** — алгоритм выбирается **снаружи** (клиент/конфиг подставляет нужную
  стратегию) и обычно не меняется по ходу; варьируется *как* делать одно и то же
  (разные сортировки, разные способы оплаты).
- **State** — объект **сам переключает** своё поведение при смене внутреннего
  состояния (заказ: `new → paid → shipped`, и методы ведут себя по-разному).
  Структурно похожи (поведение за интерфейсом), но у State переходами управляет сам
  объект, а смысл — моделировать конечный автомат.

## Вопрос 7
Упаковав действие в объект с `execute()` (и, скажем, `undo()`), получаешь:
1. **undo/redo** — храним историю выполненных команд и откатываем;
2. **очередь/отложенное выполнение/лог** — команду можно положить в очередь,
   сериализовать, повторить, выполнить позже.
Прямой вызов функции даёт только «сделать сейчас»; команда превращает действие в
**данные**, которыми можно управлять.

## Вопрос 8
**Singleton = глобальное состояние с глобальной точкой доступа.** Минусы: скрытая
зависимость (класс тайком дёргает синглтон — не видно в сигнатуре), тяжело
тестировать (общий стейт течёт между тестами, не подменить мок), скрытая
связанность.

В Node модуль **и так** кэшируется — экспортируешь экземпляр, и он один на процесс.
В Nest **DI-контейнер** по умолчанию делает провайдеры синглтонами и внедряет их
через конструктор — ты получаешь «один экземпляр», но зависимость **явная** и
подменяемая в тестах. Поэтому ручной Singleton почти не нужен.

## Вопрос 9
- **Strategy** → просто **функция-параметр** (`arr.sort(compareFn)`, коллбэк).
- **Singleton** → **модуль** (импортируется один раз, кэшируется).
- **Command** → **замыкание** (`() => doThing(x)`), которое можно положить в массив/
  очередь.
- **Observer** → `EventEmitter`/коллбэки уже встроены.
- **Factory** → обычная функция, возвращающая объект.
Идиома JS часто короче «классического» ООП-паттерна — паттерн из книги имеет смысл,
только когда проблема реально доросла до него.
