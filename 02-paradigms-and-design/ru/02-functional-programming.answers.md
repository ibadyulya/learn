## Вопрос 1
Чистая функция: (1) **детерминирована** — тот же вход всегда даёт тот же выход;
(2) **без побочных эффектов** — ничего внешнего не меняет и ни от чего внешнего не
зависит.

Следствия: **тестируемость** — вход → проверил выход, моки и подготовка состояния
не нужны; **кэшируемость** — раз выход зависит только от входа, результат можно
запомнить (мемоизация); **параллельность** — нет общего изменяемого состояния,
значит нет гонок, функции можно гонять параллельно безопасно.

## Вопрос 2
- `a` — **чистая**: только вход → выход.
- `b` — **грязная**: `Array.sort()` мутирует исходный массив (побочный эффект на
  аргументе).
- `c` — **грязная**: `Date.now()` недетерминирована (разный выход при одном «входе»).
- `d` — **чистая**: `[...arr]` копирует, сортируется копия, оригинал цел.

## Вопрос 3
React/Redux определяют «что-то изменилось» **сравнением по ссылке** (`prev ===
next`), это дёшево. Если мутировать `state.items.push(x)`, ссылка на объект
**осталась той же** → React/Redux решают «ничего не поменялось» → нет ре-рендера/
обновления. Нужно создавать **новый** объект/массив (`[...state.items, x]`), тогда
ссылка меняется и изменение замечается. Мутация ломает всю модель обнаружения
изменений.

## Вопрос 4
```ts
const result = users
  .filter(u => u.active)
  .map(u => u.name.toUpperCase());
```
Никакого ручного состояния и мутаций — «что», а не «как».

## Вопрос 5
- **Каррирование** — превратить `f(a, b, c)` в цепочку `f(a)(b)(c)`.
- **Частичное применение** — зафиксировать часть аргументов, получив новую функцию.
```ts
const log = (level: string) => (msg: string) => console.log(`[${level}] ${msg}`);
const error = log('ERROR');   // специализация
error('disk full');           // [ERROR] disk full
```
Удобно для переиспользуемых специализаций и подстановки в `map`/обработчики без
обёрток.

## Вопрос 6
Эффекты неизбежны — без I/O программа ничего не делает. ФП их **не запрещает, а
локализует**: держит ядро логики чистым, а эффекты (сеть, БД, консоль) выносит
тонким слоем на **края** приложения. Так основная логика остаётся тестируемой и
предсказуемой, а «грязь» собрана в предсказуемых местах.

## Вопрос 7
```ts
const compose = (...fns: Function[]) => (x: any) =>
  fns.reduceRight((acc, fn) => fn(acc), x);

// проверка:
const f = (n: number) => n + 1;
const g = (n: number) => n * 2;
const h = (n: number) => n - 3;
compose(f, g, h)(10);   // f(g(h(10))) = f(g(7)) = f(14) = 15
```
`reduceRight` идёт справа налево — ровно порядок вложенности `f(g(h(x)))`.
