# Функциональное программирование

> 🌐 English version: [02-functional-programming.md](../en/02-functional-programming.md)

Парадигма, где программа собирается из **чистых функций** и **неизменяемых
данных**. Читается как рассказ: из одного свойства — предсказуемости — вырастает
всё остальное.

Сквозная идея темы:

> **ФП строится на одном требовании: функция должна быть чистой — тот же вход
> всегда даёт тот же выход и никаких скрытых эффектов. Из этой предсказуемости
> растёт всё: композиция, лёгкое тестирование, безопасная параллельность,
> декларативность. Побочные эффекты не запрещены — их выносят на края программы.**

---

## 1. Чистые функции — сердце всего

**Чистая функция** удовлетворяет двум условиям:
1. **Детерминизм** — тот же вход → тот же выход, всегда.
2. **Нет побочных эффектов** — не меняет ничего снаружи (глобалы, аргументы, DOM,
   БД, консоль) и ни от чего внешнего не зависит.

```ts
const add = (a: number, b: number) => a + b;        // чистая: только вход → выход
let total = 0;
const addImpure = (x: number) => { total += x; };    // грязная: меняет внешнее
```
Зачем это золото: чистую функцию можно **вызывать в уме** (не надо держать в голове
состояние мира), **тестировать без моков** (вход → проверил выход), **кэшировать**
(мемоизация), **безопасно распараллеливать** (нечего ломать общего). Предсказуемость
= управляемость.

---

## 2. Неизменяемость — не меняем, а создаём новое

Данные не мутируют: вместо изменения объекта/массива создаётся **новая версия**.
```ts
// плохо (мутация)
const addItem = (cart: Item[], x: Item) => { cart.push(x); return cart; };
// хорошо (новый массив)
const addItem2 = (cart: Item[], x: Item) => [...cart, x];
```
Зачем: если данные не меняются под ногами, исчезает целый класс багов «кто-то
незаметно поменял мой массив». На неизменяемости стоит реактивность React/Redux
(сравнение по ссылке: новый объект = было изменение). Инструменты: спред,
`map/filter`, `Object.freeze`, immer.

---

## 3. Побочные эффекты — не убрать, но локализовать

Программа без эффектов бесполезна (нужно же читать БД, слать ответы, писать в
консоль). ФП не запрещает эффекты — оно их **выталкивает на края**: ядро логики
чистое, а эффекты (I/O, сеть) — тонким слоем снаружи. Так тестируемое ядро отделено
от «грязных» краёв.

---

## 4. Функции — граждане первого класса

В JS функции — обычные значения: их кладут в переменные, передают в аргументы,
возвращают. Отсюда **функции высшего порядка** (ФВП) — принимают или возвращают
функции:
```ts
[1,2,3].map(x => x * 2);              // map — ФВП, принимает функцию
const multiplier = (n: number) => (x: number) => x * n;   // возвращает функцию
```
`map/filter/reduce` — рабочие лошадки ФП в JS: вместо ручного цикла с мутацией —
декларативное «что сделать с каждым элементом».

---

## 5. Композиция и каррирование

**Композиция** — собрать большую функцию из маленьких: выход одной → вход
следующей.
```ts
const compose = (f, g) => (x) => f(g(x));
const shout = compose((s: string) => s + '!', (s: string) => s.toUpperCase());
shout('hi');   // 'HI!'
```
**Каррирование** — превратить `f(a, b)` в `f(a)(b)`, чтобы фиксировать часть
аргументов (частичное применение) и удобно комбинировать:
```ts
const add = (a: number) => (b: number) => a + b;
const add10 = add(10);   // переиспользуемая специализация
```
Зачем: маленькие чистые кусочки + композиция = сложное поведение без общего
состояния.

---

## 6. Декларативно, а не императивно

Императив описывает **как** (шаги, циклы, мутации); декларатив — **что** (результат).
```ts
// императивно
let evens = []; for (const n of nums) if (n % 2 === 0) evens.push(n);
// декларативно
const evens2 = nums.filter(n => n % 2 === 0);
```
ФП тянет к декларативности — меньше ручного управления состоянием, меньше места для
ошибки.

---

## ФП и ООП — не враги

Ложная дихотомия. Реальный код на TS/Node обычно **смешанный**: модульная структура
и границы — от ООП/DDD, а внутри — чистые функции, `map/filter/reduce`,
неизменяемость. React — яркий пример: компоненты как чистые функции пропсов,
неизменяемый стейт. Бери у каждой парадигмы сильное: инкапсуляция границ от ООП,
предсказуемость ядра от ФП.

---

## Формулировка для собеса

> «ФП — программирование чистыми функциями над неизменяемыми данными. Чистая
> функция детерминирована и без побочных эффектов, поэтому её легко тестировать,
> кэшировать и распараллеливать. Неизменяемость убирает баги «данные поменялись под
> ногами» и лежит в основе реактивности React/Redux. Эффекты не запрещены — их
> выносят на края, ядро держат чистым. Функции — граждане первого класса, отсюда
> ФВП и `map/filter/reduce`, композиция и каррирование. На практике ФП и ООП
> сочетают: границы от ООП, предсказуемое ядро от ФП.»
