# Основы ООП

> 🌐 English version: [01-oop-fundamentals.md](../en/01-oop-fundamentals.md)

Объектно-ориентированное программирование как способ **управлять сложностью**.
Читается как рассказ; четыре «столпа» вводятся не списком, а через задачу, которую
каждый решает.

Сквозная идея темы:

> **ООП — это упаковка данных и поведения в объекты, которые прячут своё
> устройство и общаются через понятный интерфейс. Главный столп — инкапсуляция
> (сокрытие); остальные три (абстракция, наследование, полиморфизм) обслуживают ту
> же цель: чтобы части системы можно было менять независимо.**

---

## Зачем вообще объекты

Без ООП данные и функции разбросаны отдельно: структура `user` тут, десяток
функций, которые её крутят, — там, и любой может залезть в поле напрямую. С ростом
кода никто не знает, кто и когда меняет состояние. ООП говорит: **держи данные и
операции над ними вместе, а наружу показывай только то, что нужно.** Объект — это
«коробка с состоянием и кнопками», внутренности спрятаны.

---

## 1. Инкапсуляция — спрятать состояние за интерфейсом

Самый важный столп. Объект **скрывает внутренние данные** и даёт доступ только
через методы. Снаружи не лезут в поля напрямую — просят объект что-то сделать.

```ts
class BankAccount {
  #balance = 0;                       // приватно (# — настоящий private в JS)
  deposit(sum: number) {
    if (sum <= 0) throw new Error('sum must be positive');
    this.#balance += sum;             // инвариант под контролем
  }
  get balance() { return this.#balance; }
}
```
Зачем: объект сам **сторожит свои инварианты** (баланс не станет отрицательным
из-за кривого присваивания извне). Поменяешь внутреннее представление — внешний код
не заметит, пока интерфейс тот же. Это фундамент модульности.

---

## 2. Абстракция — показать «что», спрятать «как»

Абстракция — выделить существенное и спрятать детали реализации за простым
интерфейсом. `array.sort()` ты зовёшь, не зная алгоритма; `repo.save(user)` — не
зная SQL.

Инкапсуляция и абстракция — две стороны одной монеты: **абстракция про дизайн
интерфейса** (что показать), **инкапсуляция про механизм сокрытия** (как спрятать
остальное).

---

## 3. Наследование — переиспользовать через «is-a»

Класс-наследник получает поля и методы родителя и может их дополнять/переопределять.
`class Admin extends User`.

Но здесь главное предостережение: **наследование переоценено.** Оно создаёт
жёсткую связь (наследник знает внутренности предка, ломается при его изменении —
«проблема хрупкого базового класса») и часто применяется по признаку «звучит
похоже», нарушая [LSP](./03-solid.md). Правило:

> **Предпочитай композицию наследованию.** «Has-a» (объект *содержит* другой и
> делегирует ему) гибче, чем «is-a».

```ts
// вместо class Car extends Engine — композиция:
class Car { constructor(private engine: Engine) {} start() { this.engine.run() } }
```
Наследование бери, когда есть настоящее «is-a» И работает подстановка (LSP); иначе
— композиция.

## 4. Полиморфизм — один интерфейс, разные реализации

«Много форм»: разные классы отвечают на один и тот же вызов по-своему, а
вызывающий код не знает и не хочет знать, с кем конкретно говорит.

```ts
interface Shape { area(): number }
const shapes: Shape[] = [new Circle(2), new Square(3)];
shapes.forEach(s => console.log(s.area()));   // каждый считает по-своему
```
Зачем: добавить новую фигуру можно, не трогая цикл — это механизм, на котором стоит
[OCP](./03-solid.md). Полиморфизм превращает `if (type===...)` в вызов метода.

Виды: **subtype-полиморфизм** (через интерфейсы/наследование, как выше),
**параметрический** (дженерики — `Array<T>`), **ad-hoc** (перегрузка). На собесе
почти всегда имеют в виду первый.

## ООП в JavaScript: классы — это сахар над прототипами

Важная особенность (детали — в [this-prototypes-inheritance](../../01-js-typescript/ru/05-this-prototypes-inheritance.md)):
в JS нет «настоящих» классов как в Java. `class` — синтаксический сахар над
**прототипным** наследованием: объект ссылается на объект-прототип, откуда берёт
методы. `extends` выстраивает цепочку прототипов. Понимать это нужно, чтобы не
удивляться `this`, `Object.create`, и почему методы живут в одном месте, а не
копируются в каждый экземпляр.

## Формулировка для собеса

> «ООП упаковывает состояние и поведение в объекты, чтобы управлять сложностью.
> Инкапсуляция — скрыть данные за методами, чтобы объект сам берёг свои инварианты
> и внутренности можно было менять, не задевая клиентов. Абстракция — показать
> «что», спрятать «как». Полиморфизм — один интерфейс, разные реализации; на нём
> стоит OCP. Наследование — переиспользование по is-a, но оно создаёт жёсткую связь
> и хрупкость, поэтому по умолчанию предпочитаю композицию (has-a) и беру
> наследование только при настоящем is-a с соблюдением LSP. В JS классы — сахар над
> прототипным наследованием.»
