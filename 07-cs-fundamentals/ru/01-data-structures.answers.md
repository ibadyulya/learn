# Структуры данных — разборы

## Вопрос 1
- **Массив:** доступ по индексу **O(1)** (адрес считается), но вставка/удаление в середину
  **O(n)** (сдвиг элементов).
- **Связный список:** доступ к i-му **O(n)** (идти по ссылкам), но вставка/удаление при
  известном узле **O(1)** (перецепить ссылки).
Выбор: нужен быстрый доступ по позиции/в основном чтение → **массив**; много вставок/удалений
в известных местах и не нужен индекс → **список**.

## Вопрос 2
- **Стек — LIFO** (последний вошёл — первый вышел). Задача: **undo/redo**, стек вызовов,
  обход в глубину (DFS), проверка сбалансированности скобок.
- **Очередь — FIFO** (первый вошёл — первый вышел). Задача: **планирование задач**,
  буфер сообщений, обход в ширину (BFS).

## Вопрос 3
Хеш-функция превращает ключ в **позицию в массиве** напрямую, без перебора → доступ/вставка
в среднем **O(1)**. **Коллизия** — когда два разных ключа дают одну позицию; их разрешают
списком в ячейке или пробированием. При **плохой** хеш-функции/переполнении коллизий много,
и в **худшем случае** всё вырождается в один список → **O(n)**. На практике при хорошем хеше
и ресайзе — O(1) амортизированно.

## Вопрос 4
**BST** хранит элементы упорядоченно (левое поддерево < узел < правое), поэтому поиск идёт
делением пополам — **O(log n)** в **сбалансированном** дереве. Если дерево
**несбалансированное** (вставляли уже отсортированные данные), оно вырождается в цепочку —
фактически связный список, и поиск деградирует до **O(n)**. Поэтому используют
самобалансирующиеся деревья (AVL, red-black, B-tree).

## Вопрос 5
**Куча (heap)** — структура с быстрым доступом к **минимуму или максимуму** (в корне); основа
**очереди с приоритетом**. Вставка нового элемента и извлечение экстремума — **O(log n)**
(просеивание вверх/вниз). Нужна там, где постоянно берут «самый приоритетный»: планировщики,
алгоритм Дейкстры, top-K.

## Вопрос 6
**Хеш-таблицу** (`Map`): ключ — слово, значение — счётчик. Проход по тексту, для каждого
слова `count[word] = (count[word] ?? 0) + 1` — в среднем **O(1)** на слово, итого **O(n)** на
весь текст. Порядок не важен, нужен быстрый доступ по ключу — идеально для подсчёта частот.

## Вопрос 7
Обычный массив плох: извлечение из начала (`shift`) — **O(n)** (сдвиг всех элементов). Лучше
**очередь** на основе связного списка или кольцевого буфера — enqueue в конец и dequeue из
начала за **O(1)**. (В JS для больших объёмов берут структуру-очередь, а не `array.shift()`.)
