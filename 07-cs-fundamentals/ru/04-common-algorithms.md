# Типовые алгоритмы и приёмы

> 🌐 English version: [04-common-algorithms.md](../en/04-common-algorithms.md)

Набор приёмов, которые закрывают целые классы задач на собесе. Читается как рассказ.

Сквозная идея темы:

> **Большинство алгоритмических задач решаются несколькими **типовыми приёмами**. Умение
> — не вызубрить решения, а **узнать паттерн** задачи и приложить нужный приём: два
> указателя, скользящее окно, BFS/DFS, динамическое программирование, жадный.**

---

## Два указателя (two pointers)

Два индекса двигаются по структуре (навстречу или в одном темпе), заменяя вложенный цикл.
На **отсортированном** массиве найти пару с суммой `target`:
```js
let l = 0, r = arr.length - 1;
while (l < r) {
  const sum = arr[l] + arr[r];
  if (sum === target) return [l, r];
  sum < target ? l++ : r--;      // двигаем нужный указатель
}
```
Было бы O(n²) перебором пар — стало **O(n)**. Признак: отсортированный массив, пара/тройка,
палиндром, слияние.

## Скользящее окно (sliding window)

Поддерживаем «окно» (подотрезок), двигая границы, вместо пересчёта с нуля. Для задач о
**подстроке/подмассиве**: самая длинная подстрока без повторов, максимальная сумма окна
длины k.
```js
// max сумма окна длины k — O(n) вместо O(n*k)
let sum = 0, max = -Infinity;
for (let i = 0; i < arr.length; i++) {
  sum += arr[i];
  if (i >= k) sum -= arr[i - k];   // сдвинули окно: добавили новый, убрали старый
  if (i >= k - 1) max = Math.max(max, sum);
}
```
Признак: «непрерывный подотрезок», «окно», «подстрока с условием».

## BFS и DFS — обходы

Обход графа/дерева (см. [структуры данных](./01-data-structures.md)):
- **BFS (в ширину)** — по уровням, через **очередь**. Находит **кратчайший путь** в
  невзвешенном графе. «Ближайшие сначала».
- **DFS (в глубину)** — вглубь до упора, через **стек**/рекурсию. Обойти всё, найти
  компоненты связности, топосортировка, поиск пути.
Оба — **O(V + E)** (вершины + рёбра). Признак: граф, дерево, лабиринт, «достижимо ли»,
«кратчайшее число шагов».

## Динамическое программирование (DP)

Когда задача разбивается на **перекрывающиеся подзадачи** и есть **оптимальная
подструктура** (оптимум целого строится из оптимумов частей). Приём — **запоминать**
решения подзадач:
- **мемоизация** (сверху вниз): рекурсия + кэш;
- **табуляция** (снизу вверх): заполняем таблицу итеративно.
Классика — Фибоначчи: наивная рекурсия **O(2ⁿ)** (пересчитывает одно и то же), с
мемоизацией — **O(n)**. Также: рюкзак, размен монет, редакционное расстояние, пути в сетке.
Признак: «сколько способов», «минимум/максимум при выборах», «оптимально».

## Жадные алгоритмы (greedy)

На каждом шаге берём **локально лучший** выбор в надежде на глобальный оптимум. Быстро и
просто, **но работает не всегда** — только когда локальный оптимум ведёт к глобальному
(нужно доказать/проверить). Пример где работает: размен монет каноничной системой (бери
самую крупную ≤ остатка); где **не** работает: некоторые нестандартные наборы монет — там
нужен DP. Признак: «максимально/минимально», «расписание», интервалы.

---

## Как узнать приём

| Сигнал в задаче | Вероятный приём |
|---|---|
| отсортированный массив, пара/тройка | два указателя |
| непрерывный подотрезок/подстрока с условием | скользящее окно |
| граф/дерево, кратчайший путь (невзвеш.) | BFS |
| обойти всё, компоненты, пути | DFS |
| «сколько способов», оптимум при выборах, перекрытия | динамическое программирование |
| локально-жадный выбор ведёт к оптимуму | жадный |

---

## Формулировка для собеса

> «Решаю задачи узнаванием паттерна. Два указателя — заменить вложенный цикл на
> отсортированных данных (пара с суммой) → O(n). Скользящее окно — для непрерывных
> подотрезков/подстрок, двигаем границы вместо пересчёта. BFS (очередь) — кратчайший путь
> в невзвешенном графе, DFS (стек/рекурсия) — обойти всё/найти компоненты, оба O(V+E).
> Динамическое программирование — когда есть перекрывающиеся подзадачи и оптимальная
> подструктура: мемоизация или табуляция превращают экспоненту в полином (Фибоначчи 2ⁿ →
> n). Жадный — локально лучший выбор, быстро, но только когда ведёт к глобальному оптимуму.
> Сначала узнаю сигнал задачи, потом применяю приём.»
