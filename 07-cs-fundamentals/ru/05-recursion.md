# Рекурсия и перебор

> 🌐 English version: [05-recursion.md](../en/05-recursion.md)

Как решать задачу, сводя её к самой себе. Читается как рассказ; про стек вызовов см.
[event loop](../../01-js-typescript/ru/01-event-loop.md).

Сквозная идея темы:

> **Рекурсия — функция, которая вызывает саму себя, сводя задачу к **меньшей той же
> задаче**, пока не дойдёт до тривиального случая. Нужны две вещи: **базовый случай**
> (когда останавливаться) и **рекурсивный шаг** (как уменьшить задачу). Работает через
> стек вызовов; перебор с возвратом (backtracking) — рекурсия, пробующая варианты и
> откатывающаяся.**

---

## Два обязательных элемента

Любая корректная рекурсия состоит из:
1. **Базовый случай** — условие остановки, когда ответ известен без рекурсии.
2. **Рекурсивный шаг** — свести к **меньшему** экземпляру той же задачи.
```js
function factorial(n) {
  if (n <= 1) return 1;            // базовый случай — стоп
  return n * factorial(n - 1);    // шаг — задача меньше на 1
}
```
**Без базового случая** (или если шаг не уменьшает задачу) — бесконечная рекурсия →
переполнение стека.

---

## Стек вызовов

Каждый вызов функции кладёт **кадр** на стек вызовов (см.
[event loop](../../01-js-typescript/ru/01-event-loop.md)); при возврате кадр снимается.
Рекурсия наращивает стек на каждый уровень вложенности:
```
factorial(3) → factorial(2) → factorial(1)   ← стек глубиной 3
             ←     2        ←     1           ← сворачиваем обратно
```
Отсюда ограничение: **слишком глубокая рекурсия → stack overflow** (стек конечен). Для
очень глубоких/больших `n` иногда переписывают в итерацию или используют хвостовую
рекурсию (где движок может не наращивать стек — но в JS это ненадёжно поддержано).

---

## Рекурсия против итерации

Любую рекурсию можно выразить циклом и наоборот (цикл + явный стек). Что выбрать:
- **рекурсия** чище для **древовидных/делимых** задач: обход дерева, «разделяй и властвуй»
  (merge sort), DFS (см. [алгоритмы](./04-common-algorithms.md)) — код повторяет структуру
  задачи;
- **итерация** проще и без риска переполнения для линейных задач (сумма массива, простой
  счётчик).
Правило: **структура задачи древовидная/рекурсивная → рекурсия; линейная → цикл.**

---

## Backtracking — перебор с возвратом

Рекурсивный приём «попробуй — зайди глубже — откатись, если тупик». Строим решение по
шагам; на каждом пробуем варианты, рекурсивно идём дальше, а если ветка не ведёт к решению
— **отменяем выбор** (backtrack) и пробуем следующий.
```
для каждого варианта на текущем шаге:
  выбрать вариант
  если решение полное → записать
  иначе → рекурсивно перейти к следующему шагу
  отменить выбор (backtrack)
```
Классика: перестановки/сочетания, судоку, N ферзей, поиск пути в лабиринте. По сути это
**DFS по дереву решений** с отменой. Часто экспоненциально по времени (перебор), но с
отсечением ветвей (pruning) практично.

---

## Связь с динамическим программированием

Рекурсия с **перекрывающимися подзадачами** + **мемоизация** = динамическое
программирование сверху вниз (см. [алгоритмы](./04-common-algorithms.md)). Наивная рекурсия
Фибоначчи пересчитывает одно и то же (**O(2ⁿ)**); добавь кэш — станет **O(n)**. То есть
рекурсия — каркас, мемоизация превращает её из переборной в эффективную.

---

## Формулировка для собеса

> «Рекурсия — функция, сводящая задачу к меньшей себе; обязательны базовый случай (стоп) и
> рекурсивный шаг (уменьшение), иначе переполнение стека. Каждый вызов — кадр на стеке
> вызовов, поэтому слишком глубокая рекурсия падает по stack overflow — для линейных задач
> беру итерацию, рекурсию — для древовидных/делимых (обход дерева, разделяй-и-властвуй,
> DFS). Backtracking — рекурсивный перебор «выбрал → углубился → откатил при тупике» (DFS
> по дереву решений): перестановки, N ферзей, судоку. Рекурсия с перекрывающимися
> подзадачами + мемоизация = DP сверху вниз, превращает экспоненту в полином (Фибоначчи 2ⁿ
> → n).»
