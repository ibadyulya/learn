# Сортировки и поиск — разборы

> 🌐 English version: [03-sorting-searching.answers.md](../en/03-sorting-searching.answers.md)

---

## Вопрос 1
Простые сортировки для каждого элемента проходят по остальным (вложенный цикл) → **n × n =
O(n²)**. Эффективные используют **«разделяй и властвуй»**: делят массив пополам — это
**log n** уровней (сколько раз делить `n` до 1), а на каждом уровне обрабатывают все
элементы — **n**. Итого **n × log n = O(n log n)**. `log n` берётся из **деления пополам**.

## Вопрос 2
- **Merge sort:** средняя и худшая — **O(n log n)** (стабильно быстрая), **стабильна**, но
  требует **O(n) доп. памяти** (буфер для слияния).
- **Quick sort:** средняя — **O(n log n)**, **худшая — O(n²)** (плохой pivot); **на месте**
  (O(log n) памяти на стек рекурсии), **не стабильна**.
Merge предсказуемее и стабильна ценой памяти; quick экономит память и быстр на практике.

## Вопрос 3
**Стабильность** — сохранение относительного порядка элементов с **равными ключами**.
Важна при **сортировке по нескольким критериям**: отсортировал по возрасту, потом стабильно
по городу — внутри одного города порядок по возрасту сохранится. Без стабильности вторая
сортировка «перемешает» равные ключи.

## Вопрос 4
Бинарный поиск на каждом шаге сравнивает с серединой и **отбрасывает половину** оставшегося
диапазона; число шагов до одного элемента = **log₂n** → **O(log n)**. Обязательное условие —
данные **отсортированы** (иначе «отбросить половину» некорректно); если нет — сначала
сортировка (O(n log n)).

## Вопрос 5
Худший **O(n²)** у quick sort наступает при **плохом выборе pivot** — когда он регулярно
оказывается минимумом/максимумом (например, на **уже отсортированном** массиве с pivot =
первый элемент): разбиение вырождается в «1 и n-1», глубина рекурсии `n`. Избежать:
**случайный pivot**, «медиана из трёх», перемешать вход, или использовать introsort
(переключение на heap sort при глубокой рекурсии).

## Вопрос 6
Нет, на практике **не пишут свою** — встроенная почти всегда лучше и оттестирована.
`Array.prototype.sort` в V8 использует **TimSort** — гибрид merge sort и insertion sort:
стабильный, **O(n log n)**, очень эффективен на реальных (частично упорядоченных) данных.
Свои реализации — для учёбы/собеса/особых требований.

## Вопрос 7
`[10, 2, 1].sort()` без компаратора сравнивает элементы **как строки** (лексикографически):
`"10" < "2"`, потому что сравнение посимвольно и `"1" < "2"`. Починка — передать **числовой
компаратор**:
```js
[10, 2, 1].sort((a, b) => a - b);   // [1, 2, 10]
```
