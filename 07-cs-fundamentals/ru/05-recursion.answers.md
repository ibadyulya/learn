# Рекурсия и перебор — разборы

> 🌐 English version: [05-recursion.answers.md](../en/05-recursion.answers.md)

---

## Вопрос 1
1. **Базовый случай** — условие остановки, когда ответ известен без рекурсии (`n <= 1`).
2. **Рекурсивный шаг** — сведение к **меньшему** экземпляру той же задачи.
Без базового случая (или если шаг не уменьшает задачу) рекурсия **никогда не остановится**
→ бесконечные вызовы → **переполнение стека** (stack overflow).

## Вопрос 2
Каждый вызов кладёт на стек вызовов **кадр** (аргументы, локальные переменные, точка
возврата); вложенный вызов кладёт ещё кадр — стек растёт на глубину рекурсии. При возврате
кадры снимаются, и результаты «сворачиваются» обратно. **Стек конечен**, поэтому слишком
глубокая рекурсия (например, `n` = сотни тысяч) исчерпывает его → **stack overflow**.

## Вопрос 3
Да, любую рекурсию можно выразить итеративно (при необходимости — с явным стеком) и наоборот.
Выбор:
- **Рекурсия** — когда структура задачи **древовидная/делимая** (обход дерева/графа DFS,
  разделяй-и-властвуй): код повторяет структуру, читается яснее.
- **Итерация** — для **линейных** задач (сумма, счётчик) и когда важна защита от переполнения
  стека / максимальная производительность.

## Вопрос 4
**Backtracking** — рекурсивный перебор: строим решение пошагово, на каждом шаге пробуем
вариант, идём глубже; если ветка зашла в тупик — **отменяем последний выбор** и пробуем
следующий.
```
выбрать вариант → если полное решение, записать; иначе рекурсия дальше → отменить выбор
```
Это **DFS по дереву решений** с откатом. Задачи: перестановки, N ферзей, судоку, путь в
лабиринте. С отсечением заведомо плохих ветвей (pruning) практично, хотя в общем случае
экспоненциально.

## Вопрос 5
Рекурсия задаёт **каркас** (задача через подзадачи). Если подзадачи **перекрываются** (одни
и те же считаются много раз), добавляем **мемоизацию** (кэш результатов) — это и есть
**динамическое программирование сверху вниз**. Оно превращает переборную рекурсию в
эффективную: Фибоначчи с наивной рекурсией **O(2ⁿ)**, с мемоизацией — **O(n)**.

## Вопрос 6
```js
function sumTree(node) {
  if (!node) return 0;                                   // базовый случай
  return node.value + sumTree(node.left) + sumTree(node.right);  // шаг: поддеревья
}
```
Рекурсия естественна, потому что **дерево само рекурсивно**: узел = значение + левое
поддерево + правое поддерево, и функция буквально повторяет эту структуру. Итеративно
пришлось бы вручную вести стек.

## Вопрос 7
Причина — **перекрывающиеся подзадачи**: `fib(n)` пересчитывает одни и те же `fib(k)`
экспоненциально много раз (**O(2ⁿ)**), к `fib(50)` это миллиарды вызовов. Исправить:
1. **Мемоизация** (сверху вниз): кэшировать результат каждого `fib(k)` → **O(n)**;
2. **Табуляция/итерация** (снизу вверх): считать `fib` в цикле, храня два последних значения
   → **O(n)** времени, **O(1)** памяти.
