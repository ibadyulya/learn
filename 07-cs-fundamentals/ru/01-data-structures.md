# Структуры данных

> 🌐 English version: [01-data-structures.md](../en/01-data-structures.md)

Как организовать данные, чтобы операции были быстрыми. Читается как рассказ; стоимости
операций формализует [сложность/Big-O](./02-complexity-big-o.md).

Сквозная идея темы:

> **Структура данных — способ организовать данные под нужные операции. Универсальной
> «лучшей» нет: каждая структура быстра в одном и медленна в другом. Выбор структуры =
> выбор **компромисса** по стоимости доступа, поиска, вставки, удаления.**

---

## Массив (array)

Элементы подряд в памяти, доступ по индексу.
- **доступ по индексу — O(1)** (адрес считается сразу);
- **поиск по значению — O(n)** (перебор);
- **вставка/удаление в середину — O(n)** (сдвиг элементов);
- вставка в конец — амортизированно O(1) (динамический массив).
Хорош, когда нужен быстрый доступ по позиции и в основном чтение.

## Связный список (linked list)

Узлы, каждый хранит значение и **ссылку** на следующий (нет соседства в памяти).
- **доступ к i-му — O(n)** (идти по ссылкам);
- **вставка/удаление при известном узле — O(1)** (перецепить ссылки);
- нет сдвигов, но плохая локальность памяти.
Хорош, когда много вставок/удалений в известных местах и не нужен доступ по индексу.

## Стек и очередь

Ограниченные по дисциплине доступа:
- **Стек (Stack)** — **LIFO** (последний вошёл — первый вышел): push/pop с одного конца.
  История undo, стек вызовов, обход в глубину.
- **Очередь (Queue)** — **FIFO** (первый вошёл — первый вышел): enqueue/dequeue с разных
  концов. Планирование задач, обход в ширину.
Обе — O(1) на своих операциях.

## Хеш-таблица (hash map)

Ключ → значение через **хеш-функцию**, дающую позицию.
- **вставка/поиск/удаление — в среднем O(1)**;
- **нет порядка**; при **коллизиях** (два ключа в одну ячейку) — списки/пробирование, в
  худшем случае деградирует к O(n).
Рабочая лошадка: словари, кэши, дедупликация, подсчёт частот. В JS — `Map`/`Object`/`Set`.

## Деревья и куча

- **Дерево** — иерархия узлов; **бинарное дерево поиска (BST)** держит порядок (левое <
  узел < правое) → поиск/вставка **O(log n)** в **сбалансированном** (несбалансированное
  вырождается в список, O(n)). На деревьях (B-tree) стоят индексы БД (см.
  [indexing](../../05-databases/ru/02-indexing.md)).
- **Куча (heap)** — дерево с приоритетом (min/max в корне): вставка/извлечение
  экстремума — O(log n). Основа **очереди с приоритетом**.

## Граф

Узлы (вершины) + связи (рёбра). Моделирует сети: соцграфы, маршруты, зависимости.
Хранят списком смежности (обычно) или матрицей. Обходят BFS/DFS (см.
[алгоритмы](./04-common-algorithms.md)).

---

## Выбор = компромисс

| Структура | Доступ | Поиск | Вставка/удаление |
|---|---|---|---|
| Массив | O(1) по индексу | O(n) | O(n) в середину |
| Связный список | O(n) | O(n) | O(1) при известном узле |
| Хеш-таблица | — | O(1) сред. | O(1) сред. |
| BST (сбаланс.) | — | O(log n) | O(log n) |
| Куча | O(1) экстремум | O(n) | O(log n) |

Нет «лучшей» — есть подходящая под операции задачи.

---

## Формулировка для собеса

> «Структура данных — способ организовать данные под операции; выбор — компромисс.
> Массив: доступ по индексу O(1), но вставка/поиск O(n). Связный список: вставка/удаление
> O(1) при известном узле, доступ O(n). Стек — LIFO, очередь — FIFO, O(1). Хеш-таблица —
> в среднем O(1) на вставку/поиск, но без порядка и с деградацией при коллизиях —
> рабочая лошадка для словарей/кэшей. BST держит порядок с O(log n) в сбалансированном
> виде (на деревьях стоят индексы БД), куча даёт O(log n) на приоритет. Граф — узлы и
> рёбра, обход BFS/DFS. Беру структуру под самые частые операции задачи.»
