# Kafka vs RabbitMQ

Финал блока: вся теория из [02](./02-event-driven-messaging.md) и
[03](./03-reliability-patterns.md) ложится на две конкретные технологии. Главное —
не «фичи», а **два разных мира по природе**, из природы всё вытекает.

> **RabbitMQ — очередь (сообщение доставили — оно исчезло). Kafka — лог
> (сообщение записали в файл, оно лежит, читатели двигают свою «закладку»).**

Метафоры: **почтовый ящик, из которого письмо забирают** (Rabbit) против
**газеты, которую все читают с той страницы, где остановились** (Kafka).

---

## RabbitMQ — умный брокер очередей
Модель «доставил и забыл»:
- продюсер → очередь; консюмер забрал, обработал, **ack** → брокер **удаляет**
  сообщение, оно физически исчезает;
- живёт, пока не съели.

Маршрутизация (сильная сторона): между продюсером и очередями — **exchange**,
умный маршрутизатор, раскладывает по очередям по routing key/паттернам. Отсюда
**smart broker / dumb consumer** — логика в брокере.

Наши понятия:
- **несколько консюмеров на очередь** → **competing consumers**: каждое
  сообщение достаётся **одному** из них (так масштабируешь обработку);
- **DLQ** встроен (dead-letter exchange);
- **порядок** — FIFO в очереди, competing-консюмеры его ломают.

Хорош для: сложная маршрутизация, задачи-команды воркерам, рабочие очереди, RPC.
Мысль: **«раздать задачи воркерам».**

## Kafka — распределённый лог
Модель «записал — лежит»:
- продюсер **дописывает** в конец **топика** (append-only лог);
- сообщение **не девается после чтения**, лежит до **retention** (срок/размер);
  Kafka удаляет **по времени/размеру, не по факту прочтения**;
- консюмер держит **offset** — «закладку»; читает → двигает вперёд, ничего не
  удаляется.

Следствия:
- **разные консюмеры читают одно и то же независимо** (у каждого свой offset);
- можно **перечитать прошлое** — отмотать offset назад;
- **ack = сдвиг offset**, сообщение не удаляется.

**Партиции** — механика масштаба и порядка: топик разрезан на partitions,
сообщения раскладываются по ключу (`user_id`):
- **параллелизм** — партиции читают разные консюмеры (**consumer group** делит
  партиции между собой);
- **порядок гарантирован только внутри партиции**, не по всему топику (связанные
  события → одна партиция по ключу). Между партициями порядка нет — цена
  параллелизма.

**dumb broker / smart consumer** — брокер тупо хранит лог, логика на консюмере.

Хорош для: потоки событий, высокий throughput, много независимых потребителей,
event sourcing, аналитика, перемотка истории. Мысль: **«записать поток событий,
который многие читают в своём темпе».**

## Сравнение

| | RabbitMQ | Kafka |
|---|---|---|
| Модель | очередь | лог |
| Судьба сообщения | удаляется после ack | лежит до retention |
| Метафора | почтовый ящик | газета с закладкой |
| Прогресс | ack удаляет | offset, сообщение остаётся |
| Читатели | одному из competing-консюмеров | каждая группа читает всё независимо |
| Перечитать прошлое | нельзя (съедено) | можно (отмотать offset) |
| Порядок | FIFO в очереди (ломается) | строгий внутри партиции |
| Масштаб | competing consumers | партиции + consumer group |
| Маршрутизация | богатая (exchange) | простая (топик/партиция по ключу) |
| Ум | smart broker / dumb consumer | dumb broker / smart consumer |
| Профиль | команды воркерам, RPC | потоки событий, стриминг |

## Как выбирать (трейд-офф из [01-foundations](./01-foundations.md))
- сложная маршрутизация, раздать задания воркерам, каждое сообщение съедается
  один раз → **RabbitMQ**;
- высокий поток, много независимых потребителей, перемотка истории, event
  sourcing → **Kafka**.

> Формулировка: «RabbitMQ — очередь: доставили и удалили, богатая маршрутизация
> через exchange, competing consumers делят сообщения — про раздачу задач
> воркерам. Kafka — распределённый лог: сообщения лежат до retention, каждый
> консюмер держит свой offset и читает независимо, можно перематывать историю;
> порядок в пределах партиции, параллелизм через партиции и consumer group.
> Rabbit — smart broker/dumb consumer, Kafka наоборот. Выбор по задаче: команды
> воркерам → Rabbit, потоки событий и много читателей → Kafka.»
