# Vue

> 🌐 English version: [02-vue.md](../en/02-vue.md)

Фреймворк с реактивностью «из коробки». Читается как рассказ; сравнение с
[React](./01-react.md) — сквозное.

Сквозная идея темы:

> **Vue строится на реактивности: ты объявляешь данные, а фреймворк **отслеживает
> зависимости** и сам обновляет только те части представления, что зависят от
> изменившихся данных. В отличие от React, где ре-рендер запускаешь заменой state,
> Vue замечает изменение реактивных данных автоматически.**

---

## Реактивность — ядро Vue

Ты помечаешь данные реактивными (`ref`, `reactive`), и Vue **следит, кто их читает**.
Когда данные меняются — Vue **точечно** обновляет только зависящие от них места шаблона.
Никаких «вызвать setState»: присвоил — представление обновилось.
```vue
<script setup>
import { ref } from 'vue';
const count = ref(0);           // реактивная ячейка
function inc() { count.value++; }  // меняем — шаблон сам обновится
</script>
<template>
  <button @click="inc">Count: {{ count }}</button>
</template>
```
Механика: при рендере Vue **записывает зависимости** (какой эффект читал какой `ref`);
при изменении `ref` он **уведомляет** только эти эффекты (паттерн «наблюдатель»). Это и
есть отличие от React: React перерисовывает компонент целиком и диффит VDOM, Vue —
обновляет адресно по графу зависимостей.

## Composition API vs Options API

- **Options API** (старый стиль) — опции `data`, `methods`, `computed`, `watch` в
  объекте компонента. Просто для мелких компонентов, но логика одной фичи размазана по
  разным опциям.
- **Composition API** (современный, `<script setup>`) — вся логика в функции `setup`
  через `ref`/`reactive`/`computed`/`watch`. Логику фичи можно собрать вместе и
  **переиспользовать** через **composables** (аналог хуков React).

---

## computed против watch

- **`computed`** — **производное** значение, которое **кэшируется** и пересчитывается
  только при изменении зависимостей. Для «вывести из данных» (полное имя из имени+фамилии).
  ```js
  const fullName = computed(() => first.value + ' ' + last.value);
  ```
- **`watch`** — **побочный эффект в ответ на изменение** (запрос, запись в стор,
  логирование). Для «сделать что-то, когда изменилось».
Правило: **вычислить значение → `computed`; выполнить действие → `watch`.**

## Сравнение с React

| | React | Vue |
|---|---|---|
| Обновление | заменяешь state → ре-рендер компонента + diff VDOM | меняешь реактивные данные → адресное обновление по зависимостям |
| Реактивность | «ручная» (setState, зависимости хуков) | автоматическая (tracking) |
| Шаблон | JSX (это JS) | шаблон-синтаксис (+ опционально JSX) |
| Логика | хуки | Composition API (`ref`/`computed`/`watch`), composables |
| Общее | компоненты, однонаправленный поток данных, реактивный UI | то же |

Оба — компонентные, декларативные, с однонаправленным потоком данных. Разница в
**механизме обновления** и стиле.

## Формулировка для собеса

> «Vue — фреймворк с реактивностью из коробки: помечаю данные реактивными (`ref`/`reactive`),
> Vue отслеживает зависимости при рендере и при изменении данных точечно обновляет только
> зависящие места — в отличие от React, где ре-рендер запускаю заменой state, а diff делает
> VDOM. Пишу на Composition API (`<script setup>`), логику фич выношу в composables (как
> хуки). `computed` — кэшируемое производное значение, `watch` — побочный эффект на
> изменение. По сути React и Vue близки (компоненты, однонаправленный поток, декларативность),
> различие — в механизме реактивности: явный ре-рендер+VDOM у React против авто-трекинга у
> Vue.»
