# HTML и CSS

> 🌐 English version: [06-html-css.md](../en/06-html-css.md)

Основы разметки и стилей, которые спрашивают даже у «джаваскриптеров». Читается как
рассказ.

Сквозная идея темы:

> **HTML описывает **смысл** (что это за контент), CSS — **представление** (как он
> выглядит). Держи их разделёнными: семантический HTML даёт доступность и SEO, а CSS
> раскладывает и оформляет через блочную модель, flex/grid и каскад. Отдельная
> обязанность — доступность (a11y).**

---

## Семантический HTML — смысл, а не «дивы»

Семантические теги (`<header>`, `<nav>`, `<main>`, `<article>`, `<button>`, `<label>`)
несут **смысл**, в отличие от безликих `<div>/<span>`. Зачем:
- **доступность** — скринридеры понимают структуру (заголовки, навигация, кнопки);
- **SEO** — поисковики лучше разбирают контент;
- **предсказуемость** — `<button>` уже кликабельна с клавиатуры, `<label>` связан с
  инпутом.
Правило: тег **по смыслу**, а не «div на всё» + JS-обвязка.

---

## Блочная модель

Каждый элемент — прямоугольник из слоёв изнутри наружу: **content → padding → border →
margin**. По умолчанию `width` считается **только по content** (`box-sizing:
content-box`), из-за чего padding/border **добавляются** сверху и «ломают» ширину.
Практика — глобально:
```css
* { box-sizing: border-box; }   /* width включает padding и border — предсказуемо */
```
`margin` схлопывается между соседями по вертикали (collapsing) — частый сюрприз.

## Layout: flexbox против grid

- **Flexbox** — **одномерная** раскладка (строка **или** колонка): выравнивание,
  распределение пространства, порядок. Идеален для тулбаров, рядов кнопок, центрирования.
  ```css
  .row { display: flex; gap: 8px; justify-content: space-between; align-items: center; }
  ```
- **Grid** — **двумерная** раскладка (строки **и** колонки одновременно): сетки страниц,
  карточки, сложные макеты.
  ```css
  .grid { display: grid; grid-template-columns: repeat(3, 1fr); gap: 16px; }
  ```
Правило: **1D → flex, 2D → grid**; часто вместе (grid для страницы, flex внутри блоков).

## Каскад и специфичность

Когда несколько правил задают один стиль, побеждает **более специфичное**. Грубая
иерархия специфичности (по возрастанию): тег < класс < id < inline-стиль; `!important`
перебивает всё (и потому его избегают). При равной специфичности — **позже объявленное**.
Плюс наследование (некоторые свойства наследуются от родителя, как `color`).

Практика: держать **низкую специфичность** (классы, а не id/`!important`), чтобы стили
были предсказуемы и переопределяемы (методологии BEM, utility-CSS).

---

## Адаптивность

Одна вёрстка под разные экраны:
- **media queries** — разные стили по ширине: `@media (max-width: 768px) { ... }`;
- **mobile-first** — сначала стили для мобилы, потом расширяем под большие экраны;
- **относительные единицы** — `rem/em/%/vw/fr` вместо жёстких `px`, чтобы масштабировалось;
- гибкие раскладки (flex/grid) + `max-width`, адаптивные картинки (`srcset`).

---

## Доступность (a11y)

Чтобы сайтом могли пользоваться все, включая скринридеры и клавиатуру:
- **семантические элементы** (кнопка — `<button>`, а не `<div onclick>`);
- **`alt`** у картинок, **`<label>`** у полей;
- **ARIA**-атрибуты там, где семантики не хватает (роль, состояние) — но **сначала
  семантика**, ARIA как дополнение;
- **клавиатурная навигация** (focus, tab-порядок), видимый фокус;
- достаточный **контраст** текста.

---

## Формулировка для собеса

> «HTML — про смысл, CSS — про вид, держу их раздельно. Семантические теги дают
> доступность и SEO и работают из коробки (button, label). Блочная модель — content/
> padding/border/margin; ставлю `box-sizing: border-box`, чтобы width был предсказуем.
> Раскладка: flexbox для одномерной, grid для двумерной, часто вместе. Конфликты стилей
> решает каскад по специфичности (тег<класс<id<inline, `!important` избегаю); держу
> специфичность низкой. Адаптив — mobile-first, media queries, относительные единицы,
> гибкие сетки. И доступность: семантика, alt/label, ARIA как дополнение, клавиатура,
> контраст.»
