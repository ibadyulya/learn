# Веб-производительность

> 🌐 English version: [05-web-performance.md](../en/05-web-performance.md)

Как сделать, чтобы страница быстро загружалась и отзывчиво работала. Читается как
рассказ; опирается на [браузер/рендеринг](./04-browser-dom-rendering.md) и
[кэш/CDN](../../06-system-design/ru/07-caching-cdn.md).

Сквозная идея темы:

> **Производительность — как быстро пользователь **видит** страницу и может ею
> **пользоваться**. Два фронта: загрузка (меньше байтов и позже те, что не нужны сразу)
> и рантайм (не блокировать единственный поток). Мерить объективно — по Core Web
> Vitals, а не «на глаз».**

---

## Что и зачем меряем: Core Web Vitals

Google формализовал три метрики реального опыта:
- **LCP (Largest Contentful Paint)** — когда отрисовался **главный контент** (загрузка).
  Цель ~< 2.5с.
- **INP (Interaction to Next Paint)** — как быстро страница **реагирует** на действия
  (интерактивность; раньше был FID). Цель < 200мс.
- **CLS (Cumulative Layout Shift)** — насколько **прыгает** вёрстка при загрузке
  (визуальная стабильность). Цель < 0.1.
Смысл: быстро **показать**, быстро **откликнуться**, не **дёргать** макет.

---

## Оптимизация загрузки — меньше и позже

- **Бандлинг + минификация + сжатие** (gzip/brotli) — меньше байтов по сети.
- **Code splitting** — резать бандл на части, грузить по маршрутам/по требованию, а не
  весь фронт сразу.
- **Lazy loading** — подгружать по мере надобности: маршруты, компоненты, картинки ниже
  сгиба (`loading="lazy"`).
- **Tree-shaking** — выкинуть неиспользуемый код (работает благодаря статичности ESM,
  см. [модули](../../01-js-typescript/ru/02-modules-cjs-esm.md)).
- **Critical CSS** — инлайнить стили для первого экрана, остальное — асинхронно, чтобы не
  блокировать рендер.
- **Кэш/CDN** — статику ближе к пользователю с версионированными именами (см.
  [кэш/CDN](../../06-system-design/ru/07-caching-cdn.md)).

---

## Оптимизация ассетов

Часто **картинки — самый тяжёлый ресурс**:
- современные форматы (**WebP/AVIF**), сжатие;
- **адаптивные** картинки (`srcset` — под размер экрана), не грузить 4K на телефон;
- **lazy-load** изображений ниже сгиба;
- задавать размеры (width/height), чтобы не было скачка макета (**CLS**).
Шрифты: `font-display: swap` (не прятать текст на время загрузки), подмножества.

---

## Рантайм-производительность

- **Не блокировать поток** — длинные задачи фризят кадр (см.
  [браузер/рендеринг](./04-browser-dom-rendering.md) и
  [event loop](../../01-js-typescript/ru/01-event-loop.md)); дробить, выносить в web
  workers.
- **Виртуализация списков** — рендерить только видимые строки из тысяч.
- **Debounce/throttle** — ограничивать частые события (ввод, скролл, resize).
- Анимировать `transform/opacity`, минимизировать reflow.
- Меньше лишних ре-рендеров (см. [React](./01-react.md)).

---

## Как измерять

- **Lab** (синтетика): **Lighthouse**, DevTools — воспроизводимо, для разработки.
- **RUM** (real user monitoring): метрики с реальных пользователей — правда о проде.
Правило: **измерь → оптимизируй узкое место → перемерь**, не гадай.

---

## Формулировка для собеса

> «Производительность меряю по Core Web Vitals: LCP (когда виден основной контент), INP
> (отзывчивость на действия), CLS (стабильность макета). Загрузку оптимизирую — бандлинг,
> минификация, сжатие, code splitting и lazy loading (грузить по требованию),
> tree-shaking, critical CSS, кэш/CDN. Ассеты — современные форматы и адаптивные картинки
> с заданными размерами (против CLS), шрифты с font-display swap. В рантайме не блокирую
> поток (дроблю/worker), виртуализирую списки, debounce/throttle, анимирую transform. И
> обязательно измеряю (Lighthouse + RUM), а не оптимизирую вслепую.»
