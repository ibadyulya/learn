# Vue — разборы

> 🌐 English version: [02-vue.answers.md](../en/02-vue.answers.md)

---

## Вопрос 1
**Реактивность** — данные, помеченные реактивными (`ref`/`reactive`), за которыми Vue
**следит**. При рендере Vue **записывает зависимости** (какой участок шаблона/эффект читал
какой реактивный источник). Когда данные меняются — Vue **уведомляет** ровно те
зависимости и **точечно** перерисовывает только их. Никакого ручного «скажи, что
обновить»: присвоил — обновилось.

## Вопрос 2
- **React** — меняешь `state` (setState) → компонент **перерисовывается целиком**, React
  строит новый VDOM и **диффит** со старым, применяя различия.
- **Vue** — меняешь реактивные данные → Vue по **графу зависимостей** обновляет **только**
  затронутые узлы, без полного ре-рендера компонента.
React перерисовывает и сравнивает, Vue адресно обновляет по трекингу.

## Вопрос 3
- **Options API** — логика разложена по опциям `data`/`methods`/`computed`/`watch`; просто,
  но одна фича размазана по разным секциям.
- **Composition API** — вся логика в `setup` (`ref`/`computed`/`watch`); появился, чтобы
  **группировать логику по фиче** и **переиспользовать** её через composables (в Options
  это делалось миксинами — неявно и с конфликтами).

## Вопрос 4
- **`computed`** — для **производных значений**: кэшируется, пересчитывается только при
  изменении зависимостей, при повторном чтении отдаёт кэш. Пример: `fullName` из
  `first`+`last`.
- **`watch`** — для **побочных эффектов** на изменение: запрос, запись, лог. «Изменилось X
  → сделать Y».
`computed` эффективнее для вывода данных, потому что **не пересчитывается зря** (кэш) и
декларативен; `watch` — императивная реакция.

## Вопрос 5
**Composable** — функция, инкапсулирующая **переиспользуемую реактивную логику** (например,
`useMouse()`, `useFetch()`), собранная на Composition API. Прямой аналог — **кастомный хук
React** (`useSomething`): та же идея вынести логику с состоянием/эффектами в
переиспользуемую функцию.

## Вопрос 6
Общее: оба **компонентные**, **декларативные** (UI следует за данными), с
**однонаправленным потоком данных** и реактивным обновлением; оба поощряют композицию из
переиспользуемых кусков (хуки/composables). Принципиальное различие — **механизм
реактивности**: React перерисовывает компонент и диффит VDOM (реактивность «ручная», через
state/зависимости), Vue автоматически отслеживает зависимости и обновляет адресно.

## Вопрос 7
`ref(0)` оборачивает значение в **реактивный объект** с полем `.value` — в JS-коде
доступ/изменение идёт через `count.value` (иначе потеряешь реактивность, работая с голым
числом). В **шаблоне** Vue **автоматически разворачивает** ref верхнего уровня, поэтому
пишешь просто `count` — `.value` не нужен. Это синтаксическое удобство шаблона.
