## Вопрос 1
Семантический HTML несёт **смысл**: скринридеры и поисковики понимают структуру, а браузер
даёт поведение из коробки. `<div onclick>` вместо `<button>` теряет: **клавиатурную
доступность** (div не фокусируется и не жмётся Enter/Space), **роль** для скринридера
(«кнопка»), фокус-состояние, семантику для SEO. Всё это пришлось бы воссоздавать вручную
(tabindex, role, обработчики клавиш) — и обычно делают плохо.

## Вопрос 2
Слои изнутри наружу: **content → padding → border → margin**. `box-sizing: border-box`
включает **padding и border в `width`/`height`**: зададут ширину 200px — она и останется
200px с учётом отступов и рамки. Ставят глобально, потому что дефолтный `content-box`
**добавляет** padding/border сверху, ломая расчёты ширины — с border-box раскладка
предсказуема.

## Вопрос 3
- **Flexbox** — **одномерный**: раскладка по **одной** оси (строка **или** колонка),
  выравнивание и распределение пространства вдоль неё. Для тулбаров, рядов, центрирования.
- **Grid** — **двумерный**: строки **и** колонки **одновременно**, сетки/макеты.
Выбор: раскладываешь в одну линию → flex; нужна настоящая сетка (ряды и колонки) → grid.
Часто комбинируют (grid для страницы, flex внутри ячеек).

## Вопрос 4
Побеждает **более специфичное** правило. По возрастанию: **тег < класс < id < inline**;
`!important` перебивает всё. При равной специфичности — **позже объявленное**.
`!important` избегают, потому что он **ломает каскад**: перебить его можно только другим
`!important`, начинается «гонка важности», стили становятся непредсказуемыми и
неподдерживаемыми. Держат низкую специфичность (классы).

## Вопрос 5
**Mobile-first** — писать базовые стили под **мобильный** экран, а под большие добавлять
через `@media (min-width: ...)`. Так проще (мобильный макет обычно проще) и надёжнее для
самого распространённого случая. **Относительные единицы** (`rem/em/%/vw`) **масштабируются**
от базового размера/вьюпорта/родителя, подстраиваясь под экран и пользовательские настройки
(увеличенный шрифт); жёсткие `px` фиксированы и не адаптируются, ломая доступность и
адаптивность.

## Вопрос 6
Практики a11y: **семантические элементы**; **`alt`** у изображений; **`<label>`** у полей
формы; **ARIA** (роли/состояния) где не хватает семантики; **клавиатурная навигация** и
видимый фокус; достаточный **контраст**. «Сначала семантика» — потому что нативные элементы
**уже** доступны (фокус, роль, поведение), а ARIA **ничего не добавляет к поведению**,
только сообщает роль/состояние вспомогательным технологиям; неправильный ARIA легко сделать
**хуже**, чем правильная семантика. ARIA — заплатка, а не замена.

## Вопрос 7
```css
.parent {
  display: flex;
  justify-content: center;  /* по главной оси (горизонтали) */
  align-items: center;      /* по поперечной (вертикали) */
  min-height: 100vh;        /* чтобы было куда центрировать по вертикали */
}
```
Три строки — и блок по центру в обеих осях.
