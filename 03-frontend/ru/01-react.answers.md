## Вопрос 1
«UI = f(state)» — интерфейс есть **функция состояния**: для данного state есть
однозначная разметка. Ты описываешь **что показать**, а React сам решает, как обновить
DOM. Императивно (`el.textContent = x`, `el.classList.add`) ты вручную дёргаешь
конкретные узлы шаг за шагом — легко рассинхронить UI и данные. Декларативно — меняешь
только state, представление следует за ним.

## Вопрос 2
**Virtual DOM** — лёгкая копия дерева UI в памяти. **Reconciliation** — при изменении
состояния React строит новое виртуальное дерево, **сравнивает** со старым и применяет к
реальному DOM **только различия** (реальный DOM дорог в обновлении). **`key`** —
стабильный идентификатор элемента списка, чтобы React понял, кто «тот же», а кто
новый/удалённый. **Индекс плох**, если список меняет порядок/содержимое: при
вставке/удалении индексы сдвигаются → React решит, что изменились «не те» элементы →
лишние перерисовки и перепутанное состояние (например, ввод в input прилипнет не к той
строке).

## Вопрос 3
`useEffect` выполняет **побочные эффекты после рендера** (запросы, подписки, таймеры,
работа с DOM). **Массив зависимостей** решает, когда эффект перезапускать: `[]` — один
раз при монтировании; `[x]` — при изменении `x`; без массива — после каждого рендера.
**Функция очистки** (return) снимает подписки/таймеры перед следующим запуском/размонтированием.
Утечка без cleanup:
```tsx
useEffect(() => { const id = setInterval(tick, 1000); }, []);   // забыли clearInterval
```
Интервал живёт после размонтирования, держит замкнутые данные — утечка.

## Вопрос 4
- **`useMemo`** — кэширует **значение** (результат дорогого вычисления) между рендерами,
  пересчитывает при смене зависимостей.
- **`useCallback`** — кэширует **функцию** (стабильная ссылка), чтобы не создавать новую
  на каждый рендер (важно для пропсов в `React.memo`).
- **`useRef`** — **изменяемая ссылка**, которая **не вызывает ре-рендер**; для доступа к
  DOM-узлу или хранения значения между рендерами (таймеры, «предыдущее значение»).

## Вопрос 5
`setCount(count + 1)` использует `count`, **замкнутый в этом рендере** — при нескольких
обновлениях подряд (или в замыкании колбэка) значение устаревает, и обновления «съедают»
друг друга. `setCount(c => c + 1)` берёт **актуальное предыдущее** значение из очереди
обновлений React — надёжно при батчинге и в замыканиях. Связь с замыканиями: колбэк помнит
`count` момента создания (stale closure), функциональная форма это обходит.

## Вопрос 6
Способы: **`React.memo`** (пропустить ре-рендер при неизменных пропсах),
**`useMemo`/`useCallback`** (стабилизировать пропсы-объекты/функции), правильные **`key`**,
дробление компонентов, поднятие/локализация состояния. Для `React.memo` важна
**неизменяемость**, потому что он сравнивает пропсы **по ссылке**: если мутировать объект
на месте, ссылка та же → memo решит «не изменилось» и пропустит нужный ре-рендер; новый
объект (`{...obj}`) → новая ссылка → корректное обновление.

## Вопрос 7
**Stale closure** — колбэк/эффект «замкнул» значения **того рендера**, где создан, и при
последующих изменениях видит **устаревшее** значение (например, `count` всегда 0 в
интервале, заведённом с `[]`). Избежать: указать значение в **зависимостях** эффекта,
использовать **функциональное обновление** сеттера (`setX(prev => ...)`), либо `useRef`
для «всегда свежего» значения.
