# Память и сборка мусора

> 🌐 English version: [09-memory-garbage-collection.md](../en/09-memory-garbage-collection.md)

Как JS сам управляет памятью, по какому правилу освобождает объекты и откуда берутся
утечки. Читается как рассказ.

Сквозная идея темы:

> **Память в JS управляется автоматически: выделяется при создании значения и
> освобождается, когда до объекта больше **нельзя дотянуться** из «корней». Сборщик
> мусора работает по достижимости (mark-and-sweep). Утечка — не «GC сломался», а
> случайно удерживаемая ссылка на то, что уже не нужно.**

---

## Жизненный цикл памяти

Три шага, первый и третий — автоматические:
1. **выделение** — при создании (`{}`, `[]`, строка, замыкание);
2. **использование** — чтение/запись;
3. **освобождение** — когда значение больше не нужно; **этим занимается GC**, вручную
   память не освобождают.

Вопрос в том, **как GC понимает, что «больше не нужно»**.

---

## Достижимость и корни

Критерий не «объект не используется» (это неразрешимо), а **достижимость**: объект
жив, если до него можно **дотянуться по ссылкам от корней (GC roots)**.

Корни — заведомо живое:
- глобальный объект (`globalThis`/`window`);
- переменные и параметры **в текущем стеке вызовов**;
- замкнутые переменные живых замыканий.

```
root (стек, глобалы)
  └─► userService ──► cache ──► user   ← всё достижимо, живёт
```
Как только на объект **не осталось ни одной цепочки ссылок от корня**, он становится
недостижим и подлежит сборке. Даже если объекты ссылаются **друг на друга**, но их
«островок» оторван от корней — весь островок соберётся (поэтому современный GC не
боится циклических ссылок).

---

## Mark-and-sweep — как работает GC

Основной алгоритм в V8:
1. **mark (пометка)** — идём от корней по всем ссылкам и помечаем всё достижимое.
2. **sweep (очистка)** — всё непомеченное = недостижимое → память освобождается.

На практике V8 делает это **поколенчески** (generational): большинство объектов
живут недолго, поэтому «молодое поколение» чистится часто и быстро, «старое» — реже.
Плюс инкрементально/конкурентно, чтобы не морозить поток надолго. Детали не важны —
важен принцип: **живёт достижимое, собирается недостижимое.**

---

## Что такое утечка памяти

Утечка — объект **остаётся достижимым** (ссылка на него жива), хотя логически уже не
нужен. GC не может его забрать, память растёт. То есть утечки в JS — это **забытые
ссылки**.

Типовые источники:
- **Забытые таймеры/интервалы** — `setInterval`, который никто не `clearInterval`,
  держит замкнутые в колбэке данные вечно.
- **Не снятые слушатели событий** — `addEventListener` без `removeEventListener`;
  колбэк удерживает всё, что замкнул (см. [closures-scope](./04-closures-scope.md)).
- **Растущие глобальные структуры** — кэш/массив/`Map` в глобале, куда всё кладут и
  не чистят: достижим от корня → не собирается.
- **Отсоединённые DOM-узлы** — удалили элемент со страницы, но держите ссылку на него
  в переменной → узел и его поддерево не собираются.
- **Замыкания на тяжёлое** — колбэк, случайно замкнувший большой объект и переживший
  его надобность.

Симптом: память монотонно растёт со временем/нагрузкой и не откатывается. Ищут через
heap snapshots в DevTools (сравнение снимков — что накапливается).

---

## Слабые ссылки: WeakMap / WeakSet / WeakRef

Обычная ссылка **удерживает** объект. **Слабая** — нет: если на объект остались только
слабые ссылки, GC его соберёт.
- **`WeakMap`** (ключи — объекты) / **`WeakSet`** — записи исчезают автоматически,
  когда ключ-объект больше нигде сильно не удерживается. Идеально для кэша/метаданных,
  привязанных к объекту, без риска утечки.
- **`WeakRef`** — явная слабая ссылка на объект (редко нужна, для продвинутых
  кэшей/финализации).

```ts
const meta = new WeakMap();
meta.set(user, { lastSeen: Date.now() });   // когда user умрёт, запись уйдёт сама
```

---

## Формулировка для собеса

> «Память в JS управляется автоматически: GC освобождает объекты по **достижимости**
> — жив тот, до кого есть цепочка ссылок от корней (стек, глобалы, замыкания).
> Алгоритм — mark-and-sweep (пометить достижимое от корней, вымести остальное), в V8
> поколенчески. Циклические ссылки не проблема: оторванный от корней островок
> собирается целиком. Утечка — это **забытая ссылка**: не снятый слушатель/таймер,
> растущий глобальный кэш, отсоединённый DOM-узел, замыкание на тяжёлое. Лечится
> уборкой ссылок (`removeEventListener`, `clearInterval`) и слабыми коллекциями
> `WeakMap`/`WeakSet`, которые не мешают сборке.»
