# Типы, приведение и равенство

> 🌐 English version: [07-types-coercion-equality.md](../en/07-types-coercion-equality.md)

Почему `[] == ![]` истинно, зачем `===` и откуда «хаос» приведений. Читается как
рассказ; за кажущимся беспорядком — выводимые правила.

Сквозная идея темы:

> **В JS два сорта значений — примитивы и объекты. Примитивы копируются по значению,
> объекты — по ссылке. Когда типы в операции не совпадают, JS **неявно приводит**
> их по фиксированным правилам; `==` приводит, `===` — нет. Знай правила приведения
> и falsy-список — и «магия» исчезает. Практика: всегда `===`.**

---

## Примитивы и объекты

**7 примитивов:** `string`, `number`, `boolean`, `null`, `undefined`, `symbol`,
`bigint`. Всё остальное (объекты, массивы, функции) — **объекты**. Проверка типа —
`typeof` (с историческим багом `typeof null === 'object'`).

**Копирование:** примитив копируется **по значению**, объект — **по ссылке**.
```ts
let a = 1, b = a; b = 2;           // a === 1 — своя копия
let o = { x: 1 }, p = o; p.x = 2;  // o.x === 2 — та же ссылка
```
Отсюда: сравнение объектов через `===` сравнивает **ссылки**, а не содержимое
(`{a:1} === {a:1}` → `false`).

---

## `==` против `===`

- **`===` (строгое)** — равно, только если **тот же тип И то же значение**. Никаких
  приведений.
- **`==` (нестрогое)** — при разных типах **сначала приводит**, потом сравнивает.

Правила приведения `==` (упрощённо): число vs строка → строка к числу; boolean → к
числу (`true`→1, `false`→0); объект vs примитив → объект к примитиву. Отсюда сюрпризы:
```ts
0 == '';        // true  (оба → 0)
0 == '0';       // true
'' == '0';      // false ('' и '0' — обе строки, не приводятся)
null == undefined;  // true  (спец-правило)
null == 0;          // false (null равен только undefined)
[] == ![];      // true  (![] → false → 0; [] → '' → 0; 0 == 0)
NaN == NaN;     // false (NaN не равен ничему, включая себя)
```
**Вывод:** `==` непереходно (`0 == ''`, `0 == '0'`, но `'' != '0'`) и полно ловушек.
**Практика — всегда `===`.** Единственное оправданное исключение — `x == null` как
короткая проверка «`null` или `undefined`».

---

## Truthy / falsy

В логическом контексте значение приводится к boolean. **Falsy ровно восемь:**
```
false, 0, -0, 0n, "" (пустая строка), null, undefined, NaN
```
Всё остальное — **truthy**, включая `'0'`, `'false'`, `[]`, `{}` (пустые массив и
объект — истинны!).
```ts
if ([]) console.log('да');   // напечатает — [] truthy
Boolean('0');                 // true
```

---

## Приведение в операциях

**`+` перегружен:** если хоть один операнд строка — **конкатенация**, иначе —
сложение чисел. Отсюда классика:
```ts
1 + '2';     // '12'  (число → строка)
'5' - 2;     // 3     (у - нет строковой версии → строка к числу)
1 + 2 + '3'; // '33'  (слева направо: 3, потом '3')
[] + [];     // ''    (оба массива → пустые строки)
[] + {};     // '[object Object]'
```
Правило: `-`, `*`, `/`, `%` всегда числовые (приводят к числу); `+` строковый, если
рядом строка.

---

## `null` vs `undefined`, `NaN`

- **`undefined`** — «значения не присвоили» (необъявленное свойство, аргумент,
  `return` без значения).
- **`null`** — «намеренно пусто», ставит разработчик.
- **`NaN`** — «не число» (результат `0/0`, `Number('x')`); не равен ничему, включая
  себя → проверять `Number.isNaN(x)`.

`Object.is(a, b)` — как `===`, но с двумя отличиями: `Object.is(NaN, NaN) === true`
и `Object.is(0, -0) === false`.

---

## Формулировка для собеса

> «Значения делятся на примитивы (копируются по значению) и объекты (по ссылке),
> поэтому `{a:1} === {a:1}` — false, сравниваются ссылки. `===` сравнивает без
> приведения, `==` сначала приводит типы по правилам (число↔строка, boolean→число,
> объект→примитив), из-за чего получаются непереходные казусы вроде `0 == ''` и
> `[] == ![]`; поэтому всегда использую `===` (исключение — `x == null` для проверки
> null/undefined). Falsy восемь: false, 0, -0, 0n, '', null, undefined, NaN —
> остальное truthy, включая пустые `[]` и `{}`. `+` конкатенирует при строке, прочие
> арифметические приводят к числу. NaN не равен себе — проверяю `Number.isNaN`.»
