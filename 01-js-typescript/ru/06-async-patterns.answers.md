# Асинхронность — разборы

> 🌐 English version: [06-async-patterns.answers.md](../en/06-async-patterns.answers.md)

---

## Вопрос 1
Поток один. Синхронное ожидание заблокирует его целиком: рантайм не обработает
другие события, UI замрёт, сервер перестанет отвечать на запросы. Асинхронность
позволяет **начать** долгую операцию, освободить поток и получить результат позже
через колбэк/промис — поток остаётся свободным для другой работы.

## Вопрос 2
**pending** (ожидание), **fulfilled** (успех со значением), **rejected** (ошибка).
Переход из pending происходит **ровно один раз** и необратимо: либо в fulfilled,
либо в rejected; дальше состояние не меняется.

## Вопрос 3
Цепочка **плоская** (нет «пирамиды» вложенности), потому что `.then` возвращает
новый промис и следующий `.then` цепляется к нему. `.catch` в конце ловит ошибку из
**любого** звена выше: reject «проваливается» вниз по цепочке до ближайшего
обработчика ошибок — не нужно ловить в каждом шаге.

## Вопрос 4
`async/await` — **надстройка (сахар)** над промисами, не замена. Async-функция
**всегда возвращает промис** (значение оборачивается в resolved-промис). `await p`
под капотом эквивалентен `p.then(...)`: приостанавливает функцию, а продолжение
после `await` выполняется как **микротаска** после разрешения `p`.

## Вопрос 5
```ts
const results = await Promise.all(urls.map(url => fetch(url)));
```
Все `fetch` стартуют сразу (параллельно), ждём завершения всех. Время ≈ самой
долгой, а не сумма. (Если нужен результат даже при части ошибок — `Promise.allSettled`.)

## Вопрос 6
- **`Promise.all`** — все успешны → массив результатов; любой упал → падает весь
  (fail-fast). Сценарий: загрузить все нужные ресурсы, без любого нельзя.
- **`Promise.allSettled`** — ждёт все, отдаёт статус каждого, не падает. Сценарий:
  разослать 100 писем и узнать, какие прошли.
- **`Promise.race`** — первый завершившийся (успех/ошибка). Сценарий: запрос против
  таймаута.
- **`Promise.any`** — первый успешный, ошибки игнорит. Сценарий: несколько зеркал,
  берём то, что ответит первым успешно.

## Вопрос 7
`forEach` **не ждёт** асинхронные колбэки: он синхронно запускает все `async`-функции
и идёт дальше, поэтому `'всё сохранено'` печатается **до** завершения `save`. Починка:
```ts
// последовательно:
for (const item of items) { await save(item); }
// или параллельно:
await Promise.all(items.map(item => save(item)));
console.log('всё сохранено');
```

## Вопрос 8
```
1
4
3
2
```
Синхронно: `1`, `4`. Затем микротаски (промис) — `3` — выполняются раньше макротаск.
Потом макротаска таймера — `2`. (Микро приоритетнее макро — см. event-loop.)
