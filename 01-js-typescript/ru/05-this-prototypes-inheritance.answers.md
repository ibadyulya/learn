# `this`, прототипы и наследование — разборы

> 🌐 English version: [05-this-prototypes-inheritance.answers.md](../en/05-this-prototypes-inheritance.answers.md)

---

## Вопрос 1
От **места вызова**, а не объявления. Четыре правила (по возрастанию приоритета):
1. **обычный вызов** `fn()` → `this` = `undefined` (strict) / global;
2. **как метод** `obj.method()` → `this` = объект слева от точки;
3. **явно** `call`/`apply`/`bind` → заданный объект;
4. **`new Fn()`** → новый создаваемый объект.
Отдельно: стрелки берут `this` лексически (не имеют своего).

## Вопрос 2
Напечатает **`undefined`**. `const fn = user.hi` оторвал метод от объекта; `fn()` —
обычный вызов (правило 1), `this` не `user`. Починка:
```ts
const fn = user.hi.bind(user);   // жёстко привязать
// или
console.log(user.hi());          // звать через объект
// или
const fn2 = () => user.hi();     // обёртка-стрелка
```

## Вопрос 3
Обычная функция получает `this` **при вызове** (по четырём правилам). Стрелка
**своего `this` не имеет** — берёт из окружающей области **на момент объявления**,
как обычную переменную из замыкания. Поэтому `call/apply/bind` на неё не влияют:
у неё нет собственного слота `this`, перепривязывать нечего.

## Вопрос 4
- **`prototype`** — свойство **функции-конструктора**: объект, который станет
  прототипом для экземпляров, создаваемых через `new` (туда кладут методы).
- **`__proto__`** (`[[Prototype]]`) — ссылка **самого объекта/экземпляра** на его
  прототип.
Связь: `new User()` → `instance.__proto__ === User.prototype`.

## Вопрос 5
Движок ищет `method` на самом `obj`; не найдя — переходит по `obj.__proto__` на
прототип, ищет там; нет — на прототип прототипа, и так до `null`. Это **цепочка
прототипов**. Первое найденное вдоль цепочки и используется; если дошли до `null` —
`undefined` (или ошибка при вызове).

## Вопрос 6
Метод в `prototype` хранится **в одном месте** и **общий** для всех экземпляров —
они лишь ссылаются на прототип. Присваивание `this.method = ...` в конструкторе
создаёт **новую копию функции на каждый экземпляр** — лишняя память и никакой
выгоды. Прототип = один источник для всех.

## Вопрос 7
`class` — **синтаксический сахар** над прототипным наследованием, не новая модель.
Под капотом: методы кладутся в `Class.prototype`; `extends` связывает цепочку
(`Child.prototype.__proto__ === Parent.prototype`); `super(...)` вызывает
конструктор/метод родителя по этой цепочке. `instanceof` проверяет наличие
`Class.prototype` в цепочке объекта.

## Вопрос 8
Внутри `setInterval(function () { this.seconds++ })` обычная функция вызывается
«обычно» → `this` не экземпляр `Timer` (в strict — `undefined`, будет ошибка/`NaN`).
`seconds` не растёт. Починка — **стрелка**, которая замкнёт `this` из `start`:
```ts
start() { setInterval(() => { this.seconds++; }, 1000); }
```
(Или `bind(this)`.) Стрелка не имеет своего `this` и берёт его лексически — из
метода `start`, где `this` — экземпляр.
