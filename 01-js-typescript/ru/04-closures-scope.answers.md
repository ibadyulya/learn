# Замыкания и область видимости — разборы

> 🌐 English version: [04-closures-scope.answers.md](../en/04-closures-scope.answers.md)

---

## Вопрос 1
**Лексическая** область видимости — определяется местом, **где функция написана** в
коде. Функция берёт переменные из **места объявления**, а не вызова: не нашла в
себе — идёт вверх по цепочке к той функции, внутри которой объявлена, и так до
глобальной.

## Вопрос 2
Замыкание — **функция вместе с окружением, в котором она создана**: она сохраняет
доступ к внешним переменным даже после завершения породившей функции. `count` не
исчезает, потому что возвращённая функция **держит на него ссылку** — раз есть
ссылка, сборщик мусора не забирает переменную, хотя кадр `makeCounter` уже снят.

## Вопрос 3
Напечатает **`3, 3, 3`**. `var i` — одна function-scoped переменная на весь цикл;
все три колбэка замкнули один и тот же `i`, а к моменту срабатывания таймеров цикл
закончился и `i === 3`. Получить `0,1,2` без правки `setTimeout`:
- заменить `var` на **`let`** (привязка на каждую итерацию), или
- обернуть в IIFE, передав `i` копией: `(j => setTimeout(() => console.log(j)))(i)`.

## Вопрос 4
```ts
function once<T>(fn: () => T): () => T {
  let called = false, result: T;
  return () => {
    if (!called) { called = true; result = fn(); }
    return result;
  };
}
```
Замыкание — во внутренней функции: она помнит `called` и `result` между вызовами,
хотя `once` давно вернулась. Это приватное живучее состояние.

## Вопрос 5
```ts
const bank = (() => {
  let balance = 0;                       // приватно, снаружи не видно
  return {
    deposit: (n: number) => (balance += n),
    getBalance: () => balance,
  };
})();
bank.deposit(100);
bank.getBalance(); // 100
// bank.balance === undefined — прямого доступа нет
```
`balance` живёт только в замыкании; наружу торчат методы. Это модульный паттерн —
инкапсуляция через IIFE + замыкание.

## Вопрос 6
Каждый вызов `makeCounter()` создаёт **новый кадр** с собственной переменной
`count` и новое замыкание над ним. Возвращённые функции замыкают **разные**
переменные `count`, поэтому счётчики независимы. Делили бы состояние, только если бы
`count` был объявлен снаружи, общим для всех.

## Вопрос 7
Замыкание удерживает внешние переменные от сборки мусора. Пример:
```ts
function attach() {
  const huge = new Array(1_000_000).fill('x');  // тяжёлый объект
  document.getElementById('btn')!.addEventListener('click', () => {
    console.log(huge.length);   // колбэк замкнул huge
  });
}
```
Пока слушатель висит, замыкание держит ссылку на `huge`, и миллион элементов не
собирается — даже если больше не нужен. Лечение: снять слушатель
(`removeEventListener`) или не замыкать тяжёлое.
