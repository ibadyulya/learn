# Асинхронность: промисы, async/await

> 🌐 English version: [06-async-patterns.md](../en/06-async-patterns.md)

Как JS работает с операциями, которые **ждут** (сеть, диск, таймеры), не блокируя
единственный поток. Читается как рассказ — от колбэков к async/await. Механику
планирования (микро/макротаски) см. в [event-loop](./01-event-loop.md); здесь — про
инструменты поверх неё.

Сквозная идея темы:

> **JS однопоточный, поэтому «ждать» синхронно нельзя — заморозишь всё. Вместо
> ожидания задача уходит в фон, а результат приходит позже через колбэк. Промис —
> объект-обещание будущего значения; async/await — синтаксис поверх промисов,
> который делает асинхронный код похожим на синхронный. Всё это надстройки над event
> loop.**

---

## Почему вообще асинхронность

Поток один. Если синхронно ждать ответа сети секунду — весь рантайм стоит (не
рисует, не отвечает). Решение: **не ждать на месте**, а сказать «начни операцию, а
когда закончится — вызови вот это», и продолжить. «Вот это» — колбэк.

---

## Колбэки и callback hell

Первый способ — передать функцию, которую позовут по готовности:
```ts
readFile('a.txt', (err, data) => {
  if (err) return handle(err);
  parse(data, (err, parsed) => { /* ... */ });   // вложенность растёт
});
```
Проблемы: **«пирамида судьбы»** (вложенность на каждый шаг), ручная обработка ошибок
в каждом колбэке, тяжело комбинировать. Отсюда — промисы.

---

## Промисы — объект-обещание

**Promise** — объект, представляющий значение, которого **ещё нет**, но будет
(или будет ошибка). Три состояния:
- **pending** — ожидание;
- **fulfilled** — успешно разрешён значением;
- **rejected** — отклонён ошибкой.

Из pending переходит **ровно один раз** и необратимо. Работа с результатом — через
`.then` (успех), `.catch` (ошибка), `.finally` (в любом случае):
```ts
fetch('/api')
  .then(res => res.json())      // then возвращает новый промис → цепочка
  .then(data => use(data))
  .catch(err => handle(err))    // ловит ошибку из ЛЮБОГО then выше
  .finally(() => stopLoader());
```
Ключевое: **`.then` возвращает новый промис**, поэтому цепочка «разворачивает»
вложенность колбэков в плоскую последовательность, а один `.catch` в конце ловит
ошибку из любого звена (ошибка «проваливается» вниз по цепочке).

---

## async/await — синтаксис поверх промисов

`async/await` не заменяет промисы — это **сахар** над ними, делающий код визуально
синхронным:
```ts
async function load() {
  try {
    const res = await fetch('/api');   // await «ждёт» промис, не блокируя поток
    const data = await res.json();
    return use(data);
  } catch (err) {
    handle(err);                        // обычный try/catch вместо .catch
  }
}
```
- `async`-функция **всегда возвращает промис**.
- `await p` приостанавливает функцию, пока `p` не разрешится; **под капотом это тот
  же `.then`** — код после `await` уходит в микротаску (см. event-loop).
- ошибки ловятся обычным `try/catch`.

Читаемость выше, но помни: `await` — это `.then`, а не «остановка мира».

## Конкурентность: параллельно vs последовательно

Частая ошибка — `await` в цикле там, где операции независимы:
```ts
// медленно: ждём каждую по очереди (сумма времён)
for (const url of urls) results.push(await fetch(url));

// быстро: запускаем все сразу, ждём все (время самой долгой)
const results = await Promise.all(urls.map(u => fetch(u)));
```
Комбинаторы:
- **`Promise.all`** — ждёт все; если **хоть один** упал — весь падает (fail-fast).
- **`Promise.allSettled`** — ждёт все, возвращает и успехи, и ошибки (никогда не
  падает) — когда нужен результат по каждому.
- **`Promise.race`** — первый **завершившийся** (успех или ошибка) — таймауты.
- **`Promise.any`** — первый **успешный** (игнорит ошибки, пока есть надежда).

---

## Типичные ловушки

- **Забыл `await`** — работаешь с промисом вместо значения (`[object Promise]`,
  условия «всегда истинны»).
- **Последовательный `await` вместо `Promise.all`** — независимые операции идут
  цепочкой, время суммируется.
- **Необработанный rejection** — промис упал, `.catch`/`try` нет → `unhandledRejection`.
- **`forEach` с `async`** — `arr.forEach(async ...)` не ждёт колбэки; для
  последовательности нужен `for...of` с `await`, для параллели — `map` + `Promise.all`.

## Формулировка для собеса

> «JS однопоточный, поэтому ждущие операции делаются асинхронно — задача уходит в
> фон, результат приходит колбэком. Промис — объект будущего значения с состояниями
> pending → fulfilled/rejected, переход один раз; `.then` возвращает новый промис,
> поэтому цепочки плоские, а один `.catch` ловит ошибку из любого звена. async/await
> — сахар над промисами: async-функция всегда возвращает промис, `await` под капотом
> это `.then` (код после уходит в микротаску), ошибки — обычным try/catch. Для
> независимых задач — `Promise.all` (или allSettled), а не `await` в цикле, иначе
> время суммируется.»
