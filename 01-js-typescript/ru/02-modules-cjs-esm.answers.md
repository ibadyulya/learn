# CJS / ESM — разборы

## Вопрос 1
**CJS синхронный и динамический, ESM асинхронный и статический.**
`require('./x')` — обычный вызов функции, выполняется в рантайме в той точке,
где стоит: Node блокирующе читает файл, выполняет, возвращает `module.exports`.
Раз это код — его можно ставить в `if`, в функцию, с вычисляемым путём.

`import` — не вызов, а декларация: движок разбирает все import/export **до**
выполнения кода (фазы construct → instantiate → evaluate), строит граф
зависимостей заранее. Поэтому `import` обязан быть статичным и на верхнем уровне
— иначе граф нельзя построить до запуска. Для условной загрузки есть отдельный
динамический `import()`, он асинхронный и возвращает промис.

## Вопрос 2
- **CJS**: экспорт копируется по значению в момент `require` → импортёр получил
  снимок `0`. После `inc()` он всё равно видит `0`.
- **ESM**: импорт — живая read-only-ссылка на ячейку экспорта. После `inc()`
  импортёр видит `1`.

Ключ: ESM связывает по ссылке (binding), CJS — по значению (снимок).

## Вопрос 3
- `require('./esm.mjs')` из CJS — исторически **нельзя**: ESM грузится
  асинхронно, а `require` синхронный. Обход — динамический `await import(...)`
  (внутри async-функции), он возвращает промис с namespace.
- Наоборот — **можно**: `import fs from 'fs'`, CJS подтягивается как
  `default`-экспорт.

Мем: ESM→CJS можно синхронно, CJS→ESM — только через `import()`.

## Вопрос 4
По приоритету:
1. Расширение — `.mjs` всегда ESM, `.cjs` всегда CJS.
2. Для `.js` — поле `"type"` в ближайшем `package.json`:
   `"type":"module"` → ESM; `"commonjs"` или отсутствует → CJS.

## Вопрос 5
Event loop общий, но в ESM момент **регистрации** таймеров сдвигается:
асинхронная загрузка ESM + `top-level await` дробят выполнение (код после
`await` — микротаска), поэтому «медленный старт» вероятнее и к моменту фазы
`timers` 1мс успевает пройти → таймер созревает → `setTimeout` первым.
Но это по-прежнему **не гарантия**, а вероятность. Внутри I/O-колбэка гарантия
не меняется: `setImmediate` всегда раньше (`check` идёт сразу за `poll`).

## Вопрос 6
```js
import { fileURLToPath } from 'node:url';
import { dirname } from 'node:path';
const __dirname = dirname(fileURLToPath(import.meta.url));
```
`import.meta.url` — URL текущего модуля; `fileURLToPath` превращает его в путь.
