# Итераторы и генераторы

> 🌐 English version: [08-iterators-generators.md](../en/08-iterators-generators.md)

Как в JS устроен единый механизм перебора и как генераторы дают ленивые и даже
бесконечные последовательности. Читается как рассказ.

Сквозная идея темы:

> **Итерируемость — это договор «как меня перебирать»: объект с методом
> `Symbol.iterator` умеет отдавать элементы по одному, и на этом договоре работают
> `for...of`, спред и деструктуризация. Генератор — функция, которая умеет
> **приостанавливаться и возобновляться** (`yield`), автоматически реализуя этот
> договор; отсюда ленивость.**

---

## Протокол итерации

Два уровня договора:
- **Iterable (итерируемый)** — объект с методом `[Symbol.iterator]()`, который
  возвращает **итератор**.
- **Iterator (итератор)** — объект с методом `next()`, возвращающим
  `{ value, done }`: `value` — очередной элемент, `done` — закончилась ли
  последовательность.

```ts
const it = ['a', 'b'][Symbol.iterator]();
it.next();   // { value: 'a', done: false }
it.next();   // { value: 'b', done: false }
it.next();   // { value: undefined, done: true }
```
Именно этот протокол «дёргается» под капотом, когда пишешь `for...of`, `[...arr]`,
`const [a, b] = ...`, `Array.from`, `new Set(iterable)`. Встроенно итерируемы:
массивы, строки, `Map`, `Set`, `arguments`, NodeList. Обычный объект `{}` — **нет**
(для него `for...of` кинет ошибку; перебирают через `Object.entries`).

---

## Свой итерируемый объект

Достаточно реализовать `Symbol.iterator`:
```ts
const range = {
  from: 1, to: 3,
  [Symbol.iterator]() {
    let cur = this.from; const last = this.to;
    return { next: () => cur <= last ? { value: cur++, done: false } : { value: undefined, done: true } };
  }
};
[...range];   // [1, 2, 3]  — теперь работает for...of, спред, деструктуризация
```
Ручной итератор многословен — генераторы это упрощают.

---

## Генераторы — приостанавливаемые функции

`function*` создаёт **генератор**: функцию, которая на `yield` **замирает**, отдаёт
значение и ждёт следующего `next()`, продолжая с того же места.
```ts
function* gen() {
  yield 1;
  yield 2;
  yield 3;
}
const g = gen();
g.next();   // { value: 1, done: false }
g.next();   // { value: 2, done: false }
[...gen()]; // [1, 2, 3] — генератор сам итерируемый
```
Ключевое: код между `yield` выполняется **порциями, по запросу**. Функция не бежит
до конца — она «ставится на паузу», сохраняя всё локальное состояние (как живое
замыкание с точкой возврата).

Тот же `range` короче:
```ts
function* range(from: number, to: number) {
  for (let i = from; i <= to; i++) yield i;
}
[...range(1, 3)];   // [1, 2, 3]
```

## Ленивость и бесконечные последовательности

Раз значения считаются по требованию, можно описать **бесконечную** последователь-
ность — она не зациклит рантайм, пока берёшь конечное число:
```ts
function* naturals() { let n = 1; while (true) yield n++; }
const g = naturals();
g.next().value; // 1
g.next().value; // 2   — считается ровно столько, сколько попросили
```
Это и есть выгода ленивости: не материализуем весь список в памяти, генерируем
элемент в момент нужды (потоковая обработка, пагинация, пайплайны).

---

## Асинхронные итераторы (кратко)

Для потоков, где элементы приходят асинхронно (чтение файла кусками, страницы API),
есть **async-итераторы**: `Symbol.asyncIterator`, `async function*` с `yield`, и
перебор через `for await (const x of stream)`. Каждый шаг возвращает промис. Node-
стримы — асинхронно итерируемы.

---

## Формулировка для собеса

> «Итерируемость в JS — протокол: объект с `Symbol.iterator`, возвращающим итератор
> с `next()` → `{value, done}`. На нём работают `for...of`, спред, деструктуризация,
> `Array.from`; массивы/строки/Map/Set итерируемы, обычный объект — нет. Генератор
> (`function*`) — функция, которая на `yield` приостанавливается и возобновляется с
> сохранением состояния, автоматически реализуя протокол итератора. Отсюда
> ленивость: значения считаются по требованию, можно описать бесконечную
> последовательность и не держать весь список в памяти. Для асинхронных потоков —
> `async function*` и `for await...of`.»
