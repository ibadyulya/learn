## Задача 1

```
A
D
C
B
```

- Синхронно сверху вниз: `A`, `D`. `setTimeout` кладёт `B` в макро-очередь,
  `.then` кладёт `C` в микро-очередь.
- Стек пуст → сливаем микротаски → `C`.
- Одна макротаска → `B`.

---

## Задача 2

```
4
3
5
2
1
```

- Синхронно: `4`.
- Микро-фаза, приоритет: **сначала весь nextTick** (`3`, затем `5` — в порядке
  добавления), **потом промисы** (`2`).
- Макротаска: `1`.

---

## Задача 3

```
timer 1
promise in 1
timer 2
nextTick in 2
```

Оба колбэка лежат в очереди фазы **timers**, но макротаски берутся **по одной**,
и после каждой — турникет с микротасками.

- `timer 1` → печатает, планирует промис. Колбэк кончился → турникет → `promise in 1`.
- `timer 2` → печатает, планирует nextTick. Колбэк кончился → турникет → `nextTick in 2`.

Ключ: микротаски вклиниваются **между** двумя таймерами, хотя оба в одной фазе.

## Задача 4

```
start
1
end
2
promise
3
```

`await` — это тот же `.then`: код после `await` становится микротаской.

- Синхронно: `start`. `main()` печатает `1`, доходит до `await null` → приостанавливается,
  продолжение (`2...`) уходит в микро-очередь. Управление возвращается.
- `Promise...then` кладёт `promise` в микро-очередь **после** продолжения `main`.
- Синхронно: `end`.
- Микро-очередь `[main→2, promise]`:
  - продолжение main → `2`, снова `await` → новое продолжение (`3`) в конец очереди;
  - `promise`;
  - продолжение main → `3`.

## Задача 5

```
Порядок НЕДЕТЕРМИНИРОВАН: либо "timeout, immediate", либо "immediate, timeout".
```

`setTimeout(0)` клампится до 1мс. На верхнем уровне это гонка: успела ли пройти
1мс к моменту входа в фазу `timers`.
- быстрый старт (<1мс) → timers пропускается → `check` → `immediate` первым;
- медленный старт (≥1мс) → `timeout` первым.

Правильный ответ на собесе — **«зависит, это гонка»**, а не конкретный порядок.

## Задача 6

```
nextTick
promise
immediate
timeout
```

**Детерминировано**, потому что мы внутри I/O-колбэка (фаза `poll`).

- Колбэк `readFile` закончился → турникет: `nextTick`, затем `promise`.
- Следующая фаза после `poll` — это `check` → `immediate`.
- До `timers` дойдём только на следующем витке → `timeout`.

Внутри I/O `setImmediate` всегда раньше `setTimeout(0)`.

## Задача 7

```
start
end
nextTick
promise 1
promise 2
nextTick in promise
timeout
```

- Синхронно: `start`, `end`.
- Микро-фаза: сначала nextTick (`nextTick`), потом промисы.
- `promise 1` печатает, планирует `promise 2` (микротаска) и `nextTick in promise` (nextTick).
- Тонкость: движок дренит **всю** микро-очередь промисов до конца → `promise 2`
  выполнится **раньше**, чем `nextTick in promise`. nextTick, добавленный из
  промиса, ждёт, пока текущий слив промисов завершится.
- Затем макротаска: `timeout`.

Вывод: nextTick приоритетнее промисов **среди уже стоящих в очереди**. Но nextTick,
запланированный ИЗ промиса, не прерывает текущий слив промисов.

## Задача 8 (босс)

Гарантированная часть:

```
=== 1 ===
=== 2 ===
nextTick 1
promise 1
promise in nextTick
nextTick in promise
```

Затем **гонка timers vs check** (верхний уровень!). Два возможных хвоста:

Если первой сработает фаза timers:
```
setTimeout 1
promise in setTimeout
setImmediate 1
```
Если первой сработает фаза check:
```
setImmediate 1
setTimeout 1
promise in setTimeout
```

Разбор верхней (детерминированной) части:
- Синхронно: `=== 1 ===`, `=== 2 ===`.
- Микро-фаза начинается с nextTick: `nextTick 1` печатает, планирует `promise in nextTick`
  (микротаска — встаёт в очередь после `promise 1`).
- Слив промисов: `promise 1` (планирует `nextTick in promise`), затем `promise in nextTick`.
- Микро-очередь промисов пуста → обрабатывается nextTick, добавленный из промиса:
  `nextTick in promise`.
- Дальше libuv: `setTimeout 1` (и сразу после него турникет → `promise in setTimeout`)
  и `setImmediate 1`. Порядок этих двух групп между собой — гонка.

`promise in setTimeout` всегда идёт вплотную за `setTimeout 1` (турникет после колбэка),
а у `setImmediate 1` микротаски после нет.
